## 一、总原则

### 1. 唯一工作根

所有新文件默认只能创建在：

`/偏航`

或其已登记子目录。

除用户明确指定其他位置外，禁止：
- 在资料库根目录散落小说文件；
- 重新把`/wowoty`作为新文件生产根；
- 为同一业务另起平行根目录；
- 因一次临时任务随意增加新的一级目录。

### 2. 先判断“是否需要新文件”

以下情况默认**不新建**：
- 只是修改已有CURRENT文件中的同一职责内容；
- 只是给现有人物主档补充已确认内容；
- 只是更新项目总索引/权威索引/现有运行账；
- 只是覆盖同一稳定对象的新版本；
- 只是短期分析结果，没有后续长期调用价值。

优先原则：**能原位维护同一stable object，就不制造`最终版2/终版新版/FINAL_FINAL`。**

### 3. 新文件必须单一职责

一个新文件必须能够用一句话回答“它长期负责什么”。

若文件同时承担两个以上会独立演化的职责，应拆分；若只是同一对象的补充视图，应优先作为索引/矩阵/审计文件，而不是第二份主档。

### 4. 目录不授予事实权威

路径决定管理域，不决定故事真值。

例如：
- 放在`01_总设定与权威母版`不代表自动成为母版；
- 放在`人物资料库`不代表自动CANON；
- 放在`08_正式正文与章节状态`不代表已经COMMITTED；
- 文件名含`CURRENT / FINAL / 正史 / 终版`也不自动提升权威。

权威仍由用户明确指令、事务状态、stable身份、CANON/CURRENT索引和对应领域规则共同决定。

## 四、文件状态与命名规范

### 1. 状态词的固定含义

- `CURRENT`：当前默认调用对象/入口，不等于所有内容已发生；
- `CANON`：对应领域已确认正史，仍需服从更高权威与已提交正文；
- `CANDIDATE`：候选，不得自动进入正文事实；
- `WORKING`：当前工作过程，不具有稳定正史身份；
- `AUDIT`：审计/复核结果；
- `HISTORY / SUPERSEDED / DEPRECATED`：历史或已被替代；
- `BLOCKED`：禁止默认调用；
- `OPEN / UNKNOWN`：未定，不允许凭旧稿补值。

### 2. 禁止的版本命名方式

禁止用以下方式解决版本冲突：
- `最终版2`；
- `最终最终版`；
- `最新版真的最终`；
- `CURRENT_NEW`；
- 仅靠日期更晚就声称覆盖旧CURRENT。

同一职责已有stable object时，应优先原位更新并保留stable `library_file_id`。

### 3. 日期使用

适合带日期：
- 审计报告；
- 迁移登记；
- 一次性快照；
- 候选增量；
- 交接文档。

不建议仅靠日期区分：
- 唯一CURRENT入口；
- 长期项目规则；
- 持续维护主档；
- 唯一注册表/事务日志。

## 五、新建文件的六步路由闸

任何新文件创建前执行：

1. **NEED_GATE**：确认不能通过更新既有同职责stable object完成。
2. **DOMAIN_GATE**：在一级目录路由表中找到唯一业务域。
3. **STATUS_GATE**：明确CURRENT/CANON/CANDIDATE/WORKING/AUDIT/HISTORY/BLOCKED等状态。
4. **CONFLICT_GATE**：检查是否会生成第二CURRENT、第二人物主档、第二事务日志、第二正式正文索引等竞争对象。
5. **PERSISTENCE_GATE**：判断是否需要进入V12事务/稳定注册/人物同步/参考注册等持久治理链。
6. **INDEX_GATE**：创建后更新所有受影响索引，并回读验证路径、stable ID、状态和调用边界。

任一Gate不能回答时，先HOLD，不得“先建文件以后再整理”。

## 七、V12 CURRENT stable object特别规则

项目级新文件默认**不进入**现有56个V12 stable object集合。

只有在V12生产治理明确需要新增稳定对象时，才允许进入，并必须：
1. 先通过事务日志READ_GUARD；
2. 无`PREPARED/PARTIAL_FAILURE`租约；
3. 取得合法MAINTENANCE或CHAPTER事务；
4. 分配/登记stable `library_file_id`；
5. 更新CURRENT稳定注册表/Manifest/必要路由；
6. 重新计算依赖集合与向量；
7. 原PREWRITE按影响规则STALE；
8. 完成后重新执行PREWRITE并外部验证。

因此“在`/偏航`里新建了一个文件”与“新增V12 CURRENT stable object”是两件完全不同的事。

## 八、正文与工作稿特别规则

- 正式正文只能通过`CHAPTER / CHAPTER_REVISION`事务进入`08_正式正文与章节状态`。
- PREPARED之前需要持久草稿时，继续服从V12事务协议中的`WORKING_<LOCAL_TOKEN>`非稳定句柄规则。
- 工作稿不得自行命名成`CHUID_000002`、`R001`等尚未分配的正式ID。
- 失败尝试进入历史层，不覆盖上一份COMMITTED正文。
- 用户要求“草稿/试写”不等于授权写入正式正文CURRENT目录。

## 九、文件创建后的强制回读

任何新文件创建后至少检查：
- 路径是否符合本规则；
- stable `library_file_id`是否唯一；
- 是否意外形成第二CURRENT；
- 文件使用说明是否完整；
- 项目总索引计数是否需要更新；
- 领域专项索引是否已经同步；
- 是否触发V12依赖/PREWRITE失效；
- 是否误把候选/计划/审计写成CANON；
- 是否保留历史原件与审计链。

未通过回读不得宣布文件任务完成。

## 十、未知类型文件的默认处理

如果新文件无法明确归入任何已登记业务域：

**默认HOLD，不创建。**

处理顺序：
1. 判断它是否其实只是现有文件的更新；
2. 判断能否放入13历史或14隔离；
3. 若确属新的长期业务域，先取得用户明确授权；
4. 更新本固定路由规则与项目总索引；
5. 再创建新的目录/文件。

禁止用“先放根目录”“先随便建个文件夹”作为临时方案。
