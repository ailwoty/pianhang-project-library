>

## 六轮优化成果

| 轮次 | 做了什么 | 产出 |
|---|---|---|
| 第一轮 | 对照工业级九项标准审计模板包 | 诊断出 10 项缺口（无 README/CHANGELOG/MANIFEST、无机器数据、无自动化脚本、无度量、无发布/完结/交接等） |
| 第二轮 | 补齐工业级模块 | 新增 18 个文件：根层治理三件套、15 数据资产、16 三个可运行校验脚本、17 仪表盘、18 发布/完结/交接、Git 规范、回归清单 |
| 第三轮 | 验证整合 | 三个脚本实际运行自测通过（硬规则六项检出、回归/资产核对可用）、资产核对抓出并修复 MANIFEST 不一致、重新打包、全部框架内容整合进本系统文件夹 |
| 第四轮 | 番茄调研 + 通用化诊断 | 核验番茄官方黄金三章法则/2026 女频题材方向/平台机制，定位 9 项"偏航特化点"，产出通用化诊断报告 |
| 第五轮 | 补齐题材包与自迭代引擎 | 新增 17 个文件：19 域（6 题材包+番茄适配+黄金三章+追读+书名简介+热度雷达）、20 域（自迭代 PDCA+10章回顾+数据回流+版本历史），全部模板适配 30 万字 |
| 第六轮 | 验证整合 | 资产核对 PASS（登记 51 路径零缺失）、重新打包 78 文件、总览更新 |
| 第七轮 | 补齐爆款确定性引擎 | 新增 21 域 7 文件：爆款概率模型（诚实边界/可控项/对冲策略）、对标拆解工作流、开书可行性评分卡（<8 不开书）、黄金三章拉力测试、首秀 7 天观测协议（加码/快改/止损）、多书组合风险对冲、完本留存目标管理 |

## 框架系统分层（核心 vs 工程）

- **创作核心层（每章必用，不可裁）**：唯一权威、版本化提交、章节合同、运行态三账、要素预算、修改记录+错误禁令、独立 QA、读者视角评审。
- **工业工程层（按需启用）**：根层治理（README/CHANGELOG/MANIFEST）、自动化校验脚本、数据资产 CSV、进度仪表盘、发布/完结/交接、Git 规范、回归测试。
- 工程层设计原则：**写作时每章仍只读 5—6 个文件**；工程资产全部放"按需加载"位置，不增加日常负担。

## 快速验证命令（模板包复制到新项目后）

```bash
# 硬规则校验（每章定稿前）
python "16_自动化与校验工具/硬规则校验器.py" <正文文件.md> --min-words 2700 --max-words 3300 --banned "衡,聆" --no-start-pronoun "她,他"

# 一致性回归（每 5 章）
python "16_自动化与校验工具/一致性回归检查.py" --body <定稿目录> --registry "15_数据资产与机器可读/01_实体图谱.csv" --forbidden "金手指真相,秘密词"

# 资产核对（防文件漂移）
python "16_自动化与校验工具/资产核对.py" --manifest "00_项目资产清单_MANIFEST.md"
```
