# 言情小说项目通用框架

> 提炼自《所有人都在为她偏航》项目（2026-10-11 至 2026-10-21 全量结构盘点 + 历史任务记录分析），按使用频率和最有用点整理，可直接复制为任何新言情小说项目的目录骨架与运行流程。
>
> 使用方式：拿到新小说的简要设计后，按「五、新小说启动包」的顺序逐层填充；日常写作只跑「四、单章生产流水线」。不必把偏航全部 46 个 QA 专项照搬——本框架只保留经实战验证、高频复用的部分。

---

## 一、框架总览：五层结构

偏航项目 14 个数字目录 + 人物资料库，本质是五层结构。核心思想一句话：

> **把"作者脑中的设定"变成"可审计、可追溯、不漂移的创作流水线"。**

| 层 | 负责什么 | 对应目录 | 使用频率 |
|---|---|---|---|
| L0 入口与治理 | 每次开工先读什么、文件放哪、谁说了算 | 00 / 根级宪法 / 13 / 14 | 每任务必用 |
| L1 设定层 | 这个世界长什么样、这群人是谁 | 01 母版 / 02 世界观 / 03 地理 / 04 组织 / 05 核心机制 / 人物资料库 | 构建期高频，写作期按需 |
| L2 规划层 | 全书怎么排、每章干什么 | 06 CP线 / 07 剧情与章节合同 | 每章必用 |
| L3 生产层 | 正文产出与留档 | 08 正文 / 10 启动包 | 每章必用 |
| L4 运行态 + 质量层 | 剧情不漂移、错误不重犯、质量有闸 | 09 运行态 / 11 审核 / 12 参考 | 每章必用（运行态三账） |

三条支柱机制（偏航实战中最值钱的部分）：

1. **唯一权威**：单一母版 + 权威允许列表（CANON），旧版本全部归档只读，杜绝多版本混战。
2. **版本化提交**：正文 R 序号递增 + DELTA 差分 + 旧版 SUPERSEDED，可回滚、可追溯。
3. **章节合同制**：动笔前先把"这章干什么"锁成一行合同（场景/主线/副线/暗线/钩子），写完按合同验收。

## 三、十一个核心机制（含使用频率与最有用点）

| # | 机制 | 使用频率 | 最有用点 |
|---|---|---|---|
| 1 | **唯一启动入口 + 权威允许列表** | 每任务必用 | 防多版本混战；旧文件全部只读，不会用错 |
| 2 | **任务前置执行指令（持续更新）** | 每任务必用 | 把作者一句新要求变成永久规则；所有硬约束集中一处 |
| 3 | **创作宪法（N 条本质定义）** | 每次写正文前 | 防止设定吞掉爱情；风格/占比/禁忌最高裁决 |
| 4 | **规模基线**（卷×章×字数、爱情/事件比例、CP 分档、亲密节点保护） | 规划期定死，写作期引用 | 缩编/扩写时全书比例不崩；亲密戏这类品类核心资产"不可删减"被明文保护 |
| 5 | **章节排场合同（逐章表）** | 每章必用 | 动笔前锁定场景/主副线/暗线/钩子，写完按合同验收 |
| 6 | **运行态三账 + 世界时钟**（索引/快照/事务日志） | 每章必用 | 剧情不漂移：时间不跳、人物不越权知情、前章钩子必回收 |
| 7 | **章节要素预算** | 每章必用 | 防信息过载：核心角色≤3、冲突≤1、新钩子≤1、新概念≤1 |
| 8 | **修改过程记录 + 跨章错误禁令** | 每章必用 | 错误不重犯：每版记录诊断→刀法→验证→评分；禁令清单只增不删 |
| 9 | **独立质量审核（五视角 + 成稿检查）** | 每章定稿前 | 正史/人物/读者/语言/社会后果五视角交叉审，避免自嗨式自查 |
| 10 | **读者视角评审句式** | 每章评审时 | 用目标读者（如番茄 NP 读者）固定句式提问，诊断可复现、评分可比较 |
| 11 | **疑问裁决清单** | 逻辑卡点时 | 作者不在场也不硬编设定：冲突登记→作者拍板→再落盘 |

## 四、单章生产流水线（13 步，写每章都走一遍）

```
┌─ 写前 ───────────────────────────────────────────────┐
│ ① 读前置指令五查：错误禁令清单 → 上章定稿+其修改记录   │
│    → 宪法+文风口径 → 运行态三处 → 本章要素清单         │
│ ② 读章节合同本行（场景/主线/副线/暗线/钩子）           │
│ ③ 读本章启动包/加载包（权威约束编译）                  │
│ ④ 读人物主档 + 关系权限 + 知情边界 + 世界时钟           │
│ ⑤ 列要素清单（角色≤3 / 冲突≤1 / 钩子≤1 / 新概念≤1 + 严禁项）│
├─ 写中 ───────────────────────────────────────────────┤
│ ⑥ 起草正文 R001（按字数口径，如 2700—3300 字）        │
│ ⑦ 硬规则机器校验（字数/引号配对/破折号/禁字/段落纪律） │
│ ⑧ 写后八轮自查（剧情→人物→节奏→语言→文风→场景→重复→总验收）│
├─ 评审 ───────────────────────────────────────────────┤
│ ⑨ 修改过程记录同步（触发→本轮刀法→验证→评分）          │
│ ⑩ 读者视角评审（目标读者句式：直观缺陷→改后能否满分→修改定稿）│
│ ⑪ 定稿 → 归档 R 序号递增，旧版 SUPERSEDED              │
├─ 写后 ───────────────────────────────────────────────┤
│ ⑫ 运行态四同步：正文索引 + 状态快照（世界时钟游标）     │
│    + 事务提交日志 + 修改过程记录                        │
│ ⑬ 新错误登记进跨章禁令清单，下章写前必读               │
└────────────────────────────────────────────────────────┘
```

要点：**第⑥—⑪步可能循环多轮**（R001→诊断→R002→…→定稿），每轮都过 ⑦⑧⑨；**第⑫步是硬同步**，四账不同步 = 章节未完成。

## 五、新小说启动包（如何用简要设计充实成完整项目）

拿到新小说的简要设计（题材、女主、CP 数量、核心梗、爽点类型、禁忌）后，按下面顺序填充，每步产出都有明确落点：

| 步 | 做什么 | 落到哪 |
|---|---|---|
| 1 | 把简要设计写成《作者设计说明》：题材定位、女主一句话人设、CP 名单、核心梗、爽点/拉扯类型、写作禁忌 | 根目录 `00_作者设计说明.md` |
| 2 | 作者亲定 N 条创作宪法（言情本质/爽点/占比/人物/节奏/禁忌等），套用下方模板 | `00_入口与治理/05_小说本质定义_强制锁定.md` |
| 3 | 定规模基线：卷数 × 章数 × 单章字数、爱情/事件比例、CP 分档（S/A/B）、亲密节点数量与保护条款 | `00_入口与治理/04_任务前置执行指令_持续更新.md` 的"唯一故事基线"节 |
| 4 | 建唯一母版：女主 + 世界观一句话 + 核心事件（本题材的"六年前事故"式主线钩子）+ 金手指规则 | `01_总设定与权威母版/CURRENT_MASTER/` |
| 5 | 逐个建人物主档（套用下方人物圣经模板），并建人物总索引 | `人物资料库/` |
| 6 | 建逐章排场表：先排卷主题 → 再排每章一行（场景/主线/副线/暗线/钩子） | `07_剧情规划与章节合同/章节合同/` |
| 7 | 建空运行态：正文索引 / 状态快照（世界时钟 T0）/ 事务日志 / 修改记录占位 / 错误禁令清单空表 | `09_运行态与事务控制/`、`08_正式正文与章节状态/` |
| 8 | 写第一章启动合同（首章目标、出场人物、起始时刻、必须兑现的钩子） | `10_章节启动包与生产接口/当前章节加载包/` |
| 9 | 开始跑「四、单章生产流水线」 | — |

## 六、可直接复用的模板

### 6.1 小说本质定义模板（创作宪法）

```markdown
# 小说本质定义｜强制锁定

状态：ACTIVE / HIGHEST_CREATIVE_CONSTITUTION
锁定级别：强制锁定——任何正文、设定、规划、修订都必须以此文件为最高检验标准。

## 本质定义（作者亲定）
① 这是一本言情小说：一切设定（事件/权谋/系统/逻辑）都为人物与爱情服务，不让设定吞掉爱情。
② 爽文设定成立、情感拉扯成立：任何剧情可以不合理，但这两条必须成立。
③ 爱情线占正文约 XX%：其余 XX% 才用来交代其他事；事件线存在的唯一意义是推动爱情。
④ 事件逻辑满足读者内心的疯狂：越疯越痛越爽越爱越正确，现实"讲得通"排在"内心疯狂"之后。
⑤ 全部服务于 N 位主角的爱情纠葛：女主与每一位 CP 都有浓烈完整的爱情线，无"某位浓烈其余清淡"之分。
⑥ 必须有 Boss 链：大Boss/小Boss/受益者来自主角团与重要配角团，既是拉扯对象又是事件操盘者。
⑦ 人人有阴暗面：恶意、疯狂、不合法的一面是爱情与打脸的燃料。
⑧ 人人极端：极端性格、极端行事、极端选择，可以拿一切去赌爱情。
⑨ 快节奏：压缩铺垫、提前引爆、加快打脸频率。
⑩ CP 多线与详略：关系形态多样（虐恋/救赎/宿敌/破镜重圆/死对头变爱人…），每位 CP 有完整结局（HE/BE/开放式），不留未处理关系。
⑪ 每段关系按"战场"设计：主要战场 2—4 个 + 次要战场 5—6 个，场景无需符合逻辑，让位情感烈度。
⑫ 性关系是爱情的核心引擎：高频、多形态、直接推动关系转折（本条款按平台合规与作者尺度落地）。
⑬ 读者终检：每章必须有钩子 + 至少一个大型打脸名场面 + 一段核心情感高潮。

## 执行检验清单
| 检验项 | 通过标准 |
|---|---|
| 言情本质 | 本章核心是人物与爱情，设定没吞掉人物 |
| 爽+拉扯 | 爽文设定成立，情感拉扯成立 |
| 爱情占比 | 本章爱情/情感内容 ≥ 目标占比 |
| 读者终检 | 有钩子 + 打脸名场面 + 情感高潮 |
```

```markdown

|---|---|---|---|---|---|---|

## 全勤保底 / 亲密戏保护（硬性）
```

## 七、使用建议（偏航实战中踩过的坑 → 对应规避法）

| 坑 | 规避法 |
|---|---|
| 版本混乱、旧设定回填 | 权威允许列表 + HISTORY 全部只读 + "旧文件不自动恢复旧剧情"声明 |
| 正文越写越偏设定 | 写前必读清单硬规则；每 500 字停机核对设定 |
| 每章塞太多信息 | 要素预算（角色≤3/冲突≤1/钩子≤1/新概念≤1）|
| 前章钩子忘记回收 | 状态快照"遗留钩子"栏 + 世界时钟游标逐章核对 |
| 同一错误反复犯 | 跨章错误禁令清单，写前必读，重犯登记为流程违规 |
| 事件线喧宾夺主 | 创作宪法"爱情明线"条款 + 事件/商战占比硬上限 |
| 缩编时删掉品类核心资产 | 规模基线明文保护（如"亲密戏/拉扯场面不可删减"） |
| AI 腔/角色同质化 | 人物圣经语言指纹 + 五视角审稿（人物敌对审稿人视角专门抓"临时降智/工具人"）|
