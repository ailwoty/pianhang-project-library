# 【书名】新项目模板包｜启动手册

> 这是一套**开箱即用的言情小说项目骨架**，提炼自《偏航》项目实战。拿到新小说的简要设计后，按下面的流程把骨架填成你自己的项目。

---

## 一、使用方法（3 步）

1. **整体复制**：把整个 `新项目模板包` 文件夹复制一份，重命名为你的小说名（如 `我的新书`）。
2. **全局替换占位符**：把新文件夹里所有文件中的 `【书名】` 替换成你的书名（Obsidian 支持全局替换，或用编辑器批量替换）。
3. **按启动流程填充**：从上往下按「二、八步启动」逐文件填写，填完即可开写。

> 不需要的域可以整目录删除（如无系统题材删 `05_核心机制与系统`、短篇可合并 `02/03/04`）。删之前先看 `00_入口与治理/02_新文件路由规则_CURRENT.md`，保证路由一致。

## 二、十步启动（从简要设计到开写）

| 步 | 做什么 | 填哪个文件 |
|---|---|---|
| 1 | 写《作者设计说明》：题材定位、女主一句话人设、CP 名单、核心梗、爽点/拉扯类型、写作禁忌 | 根目录新建 `00_作者设计说明.md` |
| 2 | 作者亲定创作宪法（13 条模板已列好，逐条改/增删） | `00_入口与治理/05_小说本质定义_强制锁定.md` |
| 3 | 定规模基线：卷×章×字数、爱情/事件比例、CP 分档、亲密节点保护条款 | `00_入口与治理/04_任务前置执行指令_持续更新.md` 的"一、唯一故事基线" |
| 4 | 选题材包：按新书题材从 `19_题材包与爆款引擎/` 选一个包，按它的节奏/CP/爽点配置填母版与排场表；没有匹配就复制 `01_题材包模板.md` 自建 | `19_题材包与爆款引擎/00_题材包总索引与使用说明.md` |
| 5 | 建唯一母版：女主、世界观、核心事件、势力、卷结构、红线 | `01_总设定与权威母版/CURRENT_MASTER/【书名】_唯一上位母版.md` |
| 6 | 逐个建人物主档（复制人物圣经模板，每人一份），并登记总索引 | `人物资料库/` + `人物资料库/00_索引管理/00_核心人物档案总索引.md` |
| 7 | 建逐章排场表：先排卷主题 → 再排每章一行 | `07_剧情规划与章节合同/章节合同/00_全书逐章排场表_CURRENT.md` |
| 8 | 建空运行态：实体注册 / 状态快照（T0）/ 事务日志 / 关系底账 / 开放问题 | `09_运行态与事务控制/`（模板已就位，只填起点） |
| 9 | 写第一章启动合同 | `10_章节启动包与生产接口/当前章节加载包/00_第一章_启动合同模板.md` |
| 10 | 过黄金三章检查清单（开篇定生死，不通过不改正文） | `19_题材包与爆款引擎/09_黄金三章检查清单.md` |

第 10 步完成后，把「单章生产流水线」跑起来，全书进入日常循环。**默认规模：100 章 × 3000 字 ≈ 30 万字（可配置为 150×2000 等）。**

## 三、日常运行：单章生产流水线

写每一章都走一遍（评审段可多轮循环）：

```
写前：① 五查（禁令清单→上章定稿→宪法文风→运行态→要素清单）
      ② 读排场表本章行  ③ 读启动包  ④ 读人物主档+关系权限+世界时钟  ⑤ 列要素清单
写中：⑥ 起草 R001（2500—3200 字，均值 2800）  ⑦ 硬规则校验  ⑧ 八轮自查
评审：⑨ 修改过程记录同步  ⑩ 目标读者视角评审（缺陷→改→定稿）  ⑪ 归档 R 递增、旧版 SUPERSEDED
写后：⑫ 运行态四同步（正文索引+状态快照+事务日志+修改记录）  ⑬ 新错误登记进禁令清单
```

## 四、框架里每类文件的"权威地位"

| 文件 | 地位 | 何时读 |
|---|---|---|
| `05_小说本质定义` | 最高创作宪法 | 每次写正文/改设定前 |
| `04_任务前置执行指令` | 最高执行规则 | 每次任务开始 |
| `【书名】_唯一上位母版` | 唯一上位设定 | 任何设定冲突时裁决 |
| `00_全书逐章排场表` | 每章合同 | 动笔前读本行，写完按行验收 |
| `04_当前状态快照` | 世界真值 | 每章动笔前 + 定稿后 |
| `00_正文索引与产物命名` | 版本链 | 每次提交/定稿 |
| `00_全书错误禁令清单` | 错误档案 | 写下一章之前必读 |

## 五、可裁剪清单（按项目规模取舍）

- **短篇（30 万字内）**：可合并 `02_世界观/03_地理/04_组织` 为一个"世界设定.md"；QA 工单简化为一页检查表。
- **无系统/金手指题材**：删 `05_核心机制与系统`，母版中相应小节留空即可。
- **单 CP 或双 CP**：`06` 的 CP 档案只写实际条数；"亲密节点 ×6"规则仍建议保留。
- **不跨端协作**：`13_同步` 可删；`14_常用指令` 保留（评审句式很值钱）。

## 六、核心机制清单（不要裁掉这些）

唯一权威（单母版+允许列表）· 版本化提交（R 序号+DELTA+SUPERSEDED）· 章节合同制（先锁计划再写正文）· 运行态三账（索引/快照/日志）· 章节要素预算 · 修改过程记录+错误禁令清单 · 独立质量审核 · 读者视角评审 · 疑问裁决清单。

## 七、工业级增强模块（2026-10-21 第二轮优化新增，按需启用）

| 模块 | 位置 | 什么时候用 |

| 发布与完结 | `18_发布与完结/`（发布检查、完结复盘、交接文档） | 完本上架前、写完后、换 AI/换电脑 |
| 版本控制规范 | `13_同步/00_Git工作流规范.md` | 跨端协作、commit 规范、回滚 |

使用顺序：日常写作只需核心机制；每 5 章跑一次回归；完本走发布与完结；换环境先看交接文档。
