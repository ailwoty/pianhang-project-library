# 【书名】｜Git 工作流规范

状态：ACTIVE / 跨端协作可选
版本：【YYYY-MM-DD】

## 一、三端协作模型

```
本地（Obsidian/编辑器） ⇄ GitHub 远程仓库 ⇄ AI 助手端
```

- 本地是"主权威副本"，AI 端通过远程仓库读写，两端不直接改对方文件。
- 冲突原则：**先 pull 后写，写完即 push**；拒绝租约/冲突时检查并发，不强制推。

## 二、常用命令

| 操作 | 命令 |
|---|---|
| 查看状态 | `git status` |
| 提交全部变更 | `git add .` → `git commit -m "message"` → `git push` |
| 拉取远端更新 | `git pull` |
| 查看历史 | `git log --oneline -20` |
| 回滚某文件到指定版本 | `git checkout <commit> -- <文件路径>`（慎用，先备份） |

## 三、Commit 信息规范

```
<类型>: <一句话说明>（@<文件或范围>）

类型：feat（新增）/ fix（修复）/ rule（规则变更）/ prose（正文）/ archive（归档）/ init（初始化）
示例：
feat: 新增 15_数据资产模块（@15_数据资产/README）
prose: CH005 R003 定稿（@08_正文/CHUID_000005_R003）
rule: 作者指令：每章要素≤4（@00_入口/04_前置指令）
fix: 修正 CH003 禁字残留（@08_正文/CHUID_000003_R004）
```

## 四、版本号与标签

- 基线代号：`<书名简写>_R00X`（如 `PIANHANG_R001`），重大重建用 `ROMANCE_REBUILD_R001` 式代号。
- 发布标签：每完成一卷或一版基线，打 `git tag v<卷号>.<修订>`（如 `v1.0`）。
- 每章正文版本沿用 R 序号（R001→R002…），旧版 SUPERSEDED，不覆盖。

## 五、安全规则

1. **不提交敏感信息**：真实手机号/身份证/密码/密钥/未公开隐私一律不入库；真实人物隐私在正文库中脱敏。
2. 上传前 `git status` 确认只提交本次差分，不带入无关文件。
3. 删除文件走 `git rm` 或先移入归档目录，不直接 `rm`（可追溯）。
4. 定期 `git push` + 本地双备份（如另存 U 盘/网盘），防磁盘损坏丢稿。
