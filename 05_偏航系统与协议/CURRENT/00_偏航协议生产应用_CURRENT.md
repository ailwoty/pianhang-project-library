## APP-001｜五类协议场景生产模板：先确定叙事功能，再决定系统是否出声

所有正文系统场景优先压入以下五类之一。若一个场景同时像三类以上，通常说明系统信息过载，应拆回现实动作或只保留最重要的一类。

### A. 纯观测结算场景｜OBSERVATION_SETTLEMENT

**适用**：人物动作已经发生，四门具备足够证据，系统只负责确认是否构成有效偏航。

生产顺序：现实动作完成 → 黎栖雾先产生人物反应 → 协议后台结算 → 必要时只显示`【偏航成立。】`。

必须保留：人物行为本身比提示更有戏；提示不能替她解释“这代表爱”。

优先沉默条件：行为已经被新基线吸收、证据不足、场景不需要新增信息差，或提示删掉以后场景完全不受损。

### B. 有限窗口场景｜ACTIONABLE_WINDOW

**适用**：有效事件之后，现实中确实存在P1—P7允许的有限结构窗口。

生产顺序：先过SYS-P051完整裁决链 → HOST_CAP/EVENT_CAP → 来源链/第三方权益/碰撞/去重 → 只说明最小变量类别 → `【是否执行？】` → 黎栖雾明确选择。

叙事重点不是“系统能多强”，而是**她愿不愿意承担改变这一个变量之后仍然不可控的现实**。

禁止：窗口一出现就自动成功；把窗口写成奖励；一次授权覆盖未来；把人物最终选择当可调参数。

### C. 拒绝、不调用与系统沉默场景｜NON_USE

**适用**：黎栖雾主动拒绝、长期不调用，或协议没有足够理由出现。

生产顺序：现实机会存在/可能存在 → 她不接受、不问或系统不显示 → 现实照常前进。

叙事价值：把责任重新交还给人物，使“我不知道，但我仍然决定”成为成长的一部分。

系统如需显示，只保留`【未执行。】`；拒绝没有惩罚、债务、扣分、报复或保底补偿。

### D. 修正与证据迟到场景｜CORRECTION

**适用**：新证据使旧因果归属、基线理解或条件模型失效。

生产顺序：现实新证据先进入 → 人物/调查先感受到冲击 → 系统再最小修正，可用`【条件已变化。原判断失效。】`或`【因果归属重新评估。】`。

修正的是判断，不是历史；黎栖雾已经依据旧判断做过的选择与造成的伤害不能被系统清零。

### E. 终局长期模型诱惑场景｜TERMINAL_OBSERVATION

**适用**：长期关系模型确实满足建立条件，且叙事已经走到“她是否仍要让系统替自己解释爱”的主题节点。

前台固定为：`【长期关系模型已满足建立条件。】【是否观测？】`

核心戏不在模型答案，而在她是否选择看。拒绝后模型不生成、不缓存隐藏结论；终局也不因此摧毁协议本体。

**APP-001验收句**：系统场景先回答“它在这场戏里承担什么必要叙事功能”，答不出来就`SYSTEM_SILENT`。

## APP-002｜当前八卷协议使用弧：把SYS-P009阶段曲线编译进V1—V8生产结构

本节只锁定**结构性使用弧**，不替卷级剧情规划创建具体已发生事件。SYS-P009原先以十卷描述“前期显性—中期选择性—后期减少解释—终局最后诱惑”的阶段曲线；当前剧情生产已统一为V1—V8，因此APP层只做**节奏压缩映射**，保留阶段逻辑，不新增或削减协议能力。

### V1｜规则建立期：让读者先学会“偏航不等于爱情”

- 协议存在感可以相对高，用最清楚的四门样本建立读者语法；
- 黎栖雾容易把`DEVIATION_CONFIRMED`主观理解成“我被选择了”，但正文必须立即保留这种解释可能错误；
- 至少并置一次“动作很大但四门不成立”或“高偏航却关系更坏”的反例。

### V2｜确认与误读分化期：她开始依赖系统证明自己重要

- 系统继续可见，但不再重复教学；
- 稳定、低刺激、系统沉默的关系开始提供第一批反证；
- 同一人物的重复高成本动作若已形成新基线，系统应安静，逼黎栖雾面对“沉默到底意味着什么”。

### V3｜工具化期：她把“看见变化”转化成“安排选择空间”

- P1—P5类窗口可以更有剧情存在感，但必须展示授权、有限变量与失败可能；
- 她开始主动比较不同人的反应，正文可以写她的主观排序，却不能让协议提供客观人物排名；
- 白噪、职业判断与协议开始形成并行视角。

### V4｜测试期：她越来越会设计条件，也越来越难证明结果天然

- `HOST_INDUCED_CONTEXT / PROTOCOL_MEDIATED_CONTEXT / OBSERVATION_CONTAMINATED`进入核心戏剧区；
- 某些男主可以察觉自己正在被测量，表演性偏航与反指标博弈正式进入关系张力；
- 重点不是系统“惩罚”她，而是她发现越想消除不确定性，越在改写被测量关系的自然条件。

### V5｜现实反压期：职业伦理、第三方权利与失败结果压过系统爽感

- 强化`FAILED_OUTCOME`、第三方权益、合法路径、来源链与EVENT_CAP；
- 允许重大现实事件中系统保持安静，或偏航成立却完全没有可执行窗口；
- 系统和白噪可以给出不同角度，但任何一方都不能成为另一方的裁判。

### V6｜基线吸收期：偏航减少，成熟关系反而更清楚

- 动态基线吸收大量旧“高偏航动作”，系统存在感进一步下降；
- 允许出现重要关系进展却没有任何提示；
- 男主们对系统的反证来自各自人格：停手、等待、留下未知、允许消失、承认私心、尊重沉默等，而不是获得“抗系统能力”。

### V7｜测量逻辑反噬期：被发现的是她如何设计关系，而不是系统UI

- 有人物发现某些“自然发生”的节点其实被她设计过；
- 冲突中心落在信任、知情、自由选择与关系真实性，不写成所有人围攻一个超自然界面；
- 她必须承认：设计条件下的选择依然是真实选择，但解释权已经和自然样本不同。

### V8｜放权终局：系统仍然真实，但不再承担“该选谁”的责任

- 前台提示极少，人物已经可以不靠系统解释彼此；
- 最后诱惑不是更高P级，而是是否观测长期关系模型；
- 她拒绝的不是信息本身，而是继续让可计算稳定性替她承担爱情判断；
- 结局允许协议继续存在，真正变化的是她和协议之间的权力关系。

**APP-002验收句**：前段让系统帮助她看见偏航，中段让系统暴露测量污染，后段让人物自己夺回关系解释权；卷数变化只能重排节奏，不能重写协议能力。

## APP-004｜系统节拍预算：协议存在感服务关系戏，不得成为章节打卡器

本节是**生产节奏预算**，不是世界内规则，也不是强制计数器。

### 单场景
- 普通场景默认最多保留一个主系统节拍；后台可以有多个状态，但前台不连续倾倒。
- 一个现实动作如果已经足够改变关系，优先让人物先说话、先误解、先失态，系统提示放后或完全删除。
- 同一场景出现“偏航成立＋窗口提示＋污染解释＋长期总结”通常判定为过载，除非属于少数结构性大节点。

### 单章
- 不要求每章出现系统；**没有系统也是正常生产结果**。
- 禁止连续多章都用系统提示作章尾唯一钩子；章尾优先落在人做出的选择、关系翻面、证据进入或现实代价上。
- 若同章已有高强度危机、修罗场或秘密揭示，协议只保留能新增信息差的最小一句，避免抢走高潮解释权。

### 卷级
- V1—V2：可见度最高，用于建立规则、确认误读与“沉默非负分”的第一轮反证；
- V3—V4：从“提示是什么”转向“黎栖雾怎么使用、设计和污染提示”；
- V5—V6：现实职业伦理、失败后果、基线吸收与系统沉默成为主导；
- V7：系统不是秘密揭晓对象，测量行为与关系代价才是冲突中心；
- V8：只保留无法由普通现实替代的极少结构提示，最终落到长期模型是否观测。

### 删除测试
每一个系统节拍在PREWRITE阶段都问三遍：
1. 删除它，人物是否仍然会作出同样选择？若系统是强迫选择的必要条件，场景有问题。
2. 删除它，读者是否会失去关键的信息差/责任归属/规则标记？若不会，优先删除。
3. 保留它，是否压过人物第一反应？若会，延后、缩短或沉默。

**APP-004验收句**：协议是叙事压力计，不是章节报时器。

1. 这场戏真正发生变化的是**人物、信息、权限、计划、资源、公众版本或自我认识**中的哪一项？
2. 系统只看见了什么，它明确**看不见什么**？
3. 这场戏最后承担意义的是人物自己的选择，还是系统替作者下了结论？若是后者，退回重写。

**APP-005验收句**：先让现实成立，再让协议判断；先让人物选择，再让系统保持边界。

## APP-006｜黎栖雾的协议误读与自欺机制：系统不犯这些错，错的是她怎么解释

本节只规定**人物主观误读**，不是新增协议状态。黎栖雾可以聪明、会分析、会做白噪模型，却仍会在亲密关系里把系统提供的有限事实解释成自己最害怕或最想相信的答案。正文要把“系统说了什么”和“她以为这意味着什么”分开写。

### 八类高频误读

1. **强度谬误**：动作越大、代价越高，她越容易把它等同于“爱得更多”。纠偏必须来自关系质量本身：退出权、修复、互惠、低刺激持续性，而不是另一个更大的动作。
2. **沉默谬误**：系统没提示，她就怀疑“他没有再为我改变”。适合落在霍岑、闻惟止、顾砚秋等稳定行为已经被基线吸收的人物身上；反证只能来自现实持续，不由系统安慰。
3. **成本购买爱情谬误**：她把“一个人为她承担了真实成本”理解成“关系因此欠他一个结果”。正文必须保留：成本证明选择发生过，不购买她或任何人的爱情义务。
4. **可比性谬误**：她主观比较不同人的偏航频率、幅度、场面大小，并试图从中排序。系统不能提供排行，正文可以让她自己排序，再让不同基线与不同职责结构把这种排序击穿。
5. **可预测即安全谬误**：长期模型、稳定样本、重复行为越多，她越容易把“更可预测”当成“不会离开”。现实可以让一个高度稳定的人仍然在某个自由选择点离开，也可以让不稳定的人在关键处留下。
6. **重复即真诚谬误**：同一个人反复做相似高成本行为，她会下意识累积“证据”。SYS-P003/027要求同源衰减；正文要让她发现重复可能只是习惯、职责、补偿模式或被她设计出的可复现刺激。
7. **可控即真实谬误**：她越会设计选择空间，越容易觉得“我只是把真实答案逼出来”。实际应写成：答案仍是真实选择，但自然关系解释权下降，污染不是虚假，而是条件被她改过。
8. **修正抗拒谬误**：新证据进入后，协议允许旧判断失效；她本人却可能因为已经据此伤害过人、投入过感情或建立过自我叙事，而本能地抗拒修正。这里的戏剧重点是“承认旧解释错了会让我失去什么”。

### 生产使用规则

- 一次关系阶段只突出一到两种主误读，禁止把八类同时塞给黎栖雾，避免她像概念集合而不是人。
- 每次误读至少留下一个现实后果：她多问了一句、少说了一句、设计一次测试、拒绝一次靠近、把某人放进错误位置，或者错过一次不带系统提示的成熟关系行为。
- 纠偏不能靠系统自己说“你理解错了”。系统只修正它的判断；**人物意义必须由人重新理解。**

**APP-006验收句**：协议只给有限事实，黎栖雾负责把有限事实误读成自己的恐惧。

## APP-007｜提示后的现实后果链：系统提示不能成为场景终点

任何可见系统提示后，正文至少走完`PROMPT → HOST_INTERPRETATION → HUMAN_RESPONSE → COUNTEREVIDENCE → RESIDUE`中的后三步之一；强关系场景优先完整走完五步。

### 五步链

1. **PROMPT**：系统只给最小状态，例如`【偏航成立。】`、`【未执行。】`、`【条件已变化。】`。
2. **HOST_INTERPRETATION**：黎栖雾立刻产生她自己的理解，这一步允许偏、允许自欺、允许装作不在意。
3. **HUMAN_RESPONSE**：目标人物或第三方通过现实动作反应，可能与她的理解一致，也可能直接打脸。
4. **COUNTEREVIDENCE**：出现系统没有评价过的关系信息，例如他偏航了却不愿和她在一起、他没有新偏航却仍然留下、他为她承担成本同时也伤害了她。
5. **RESIDUE**：场景必须在现实层留下可追踪变化，至少落到关系权限、信息、计划、资源、公众版本、自我认识、信任债务中的一项。

### 不同提示的落地重点

- `【偏航成立。】`之后优先写“她怎么解释、对方是否承认这个解释”，不要停在爽点。
- `【未执行。】`之后写她承担不确定性，而不是让系统用沉默奖励她。
- `【当前无可执行窗口。】`之后写现实限制逼人物自己解决问题，避免场景泄气。
- `【条件已变化。原判断失效。】`之后写旧判断已经造成的后果继续存在。
- `FAILED_OUTCOME`类场景前台未必需要提示；重点是“系统改过的最小变量已经发生，人物仍然说不”。

### 章尾限制

系统提示原则上不单独承担章尾高潮。若必须用系统句结束，前一拍必须已经有人做出不可逆或高代价现实选择，使提示只是**重新命名读者刚刚看见的东西**，而不是凭空制造高潮。

**APP-007验收句**：系统负责点灯，戏必须发生在灯亮以后。

## APP-008｜多人修罗场与共享事件编译：同一危机逐人结算，不生成关系排行榜

多人场景先建立`SHARED_EVENT_CLUSTER`，再对每个自然人分别做偏航判断。共享危机可以相同，人物基线、因果、成本和自由选择必须独立。

### 四种常用结构

#### A. 同一危机，不同反应
同一事故、舆情、家族会议或撤离节点中，多人同时在场。生产顺序固定为：共享事实一次 → 每人自主选择 → 分别过四门 → 共享成本去重 → 前台只保留最有叙事价值的一次系统节拍。

#### B. 同一目标，不同路径
多人都想保护、见到、留下或帮助黎栖雾，但调用的现实资源不同。不能因为最终目标相同就把所有动作当同类偏航，也不能把谁“做得更大”写成系统比较。

#### C. 互斥选择
她只能接受一个时间、一个席位、一个公开版本或一条现实路径。某个窗口被接受后，其他窗口可能因现实机会成本自然`CLOSED / EXPIRED`。这不是系统惩罚，也不表示未选的人“输了”。

#### D. 修罗场中的拒绝/退出
有人靠近，有人克制，有人退出，有人公开争取。只要相对个人基线构成真实偏离，拒绝、等待、离开同样可能偏航；系统不得天然偏爱“冲上去”的动作。

### 多人场景叙事纪律

- 前台系统不连续播报十五次`【偏航成立。】`。普通多人场景只选一个结构性主提示，其余留在后台或完全沉默。
- 共享危险、共享交通、共享舆论压力等成本只记一次环境变量；个人额外成本单独判断，禁止“一场危机给所有人自动加权”。
- 读者可以从并置行为自行比较人物，但叙事不得偷换成协议官方排名。
- 若黎栖雾在修罗场中开始用系统反应做主观排名，优先调用APP-006“可比性谬误”，把这种排名写成人物缺陷而非作者结论。

**APP-008验收句**：修罗场可以同时爆炸，协议必须逐人守规矩。

## APP-009｜协议披露、被察觉与测量反噬：发现的是她的使用痕迹，不是系统UI

目标人物默认看不见协议前台。人物“知道系统存在”只能通过明确披露事件；人物“察觉自己被测量”则可以只凭黎栖雾的行为模式、重复问题、刻意安排的选择节点与异常一致的试探推断出来。两者必须分开。

### 四级披露结构

1. **行为异常被察觉**：对方只知道“她在测试我/预判我”，不知道有超自然协议。适合V3—V4起步。
2. **测量结构被识破**：对方发现多个“自然节点”其实被她提前设计过，冲突落在知情、自由答案和信任，不出现系统界面证据。
3. **有限事实披露**：黎栖雾主动承认“我有一种会记录别人是否因我改变的东西”，但可只披露与当前关系必要相关的最少部分；披露本身是关系事件，会带来后果。
4. **明确知道协议存在**：只有经过剧情明确授权的对象才能知道“偏航协议”这一事实；知道也不等于获得操作权、日志权、后台数据或宿主权限。

### 反噬场景必须写的三层

- **事实层**：她到底设计了什么，哪些节点确实受她影响。
- **选择层**：对方在这些条件下做出的决定仍然是真实决定，不能用“你操纵了环境”直接抹成假。
- **关系层**：对方有权认为“真实选择被你拿去测量”本身已经改变了亲密关系的意义。

### 禁止写法

- 男主凭聪明突然看见系统面板、读取SYS编号或破解后台；
- 一次披露后所有人共享协议知识；
- “他知道系统存在，所以以后不再受协议观测”；
- 把发现测量行为写成对系统的技术对抗赛。

**APP-009验收句**：被揭穿的是黎栖雾怎么对待关系，不是一个界面秘密本身。

## APP-010｜高狗血桥段协议转译矩阵：用系统放大责任，不用系统替现实开挂

以下桥段都可以使用偏航协议，但系统承担的功能必须受限。

| 狗血桥段 | 协议最适合承担的功能 | 禁止偷渡 | 真正高潮应落在哪里 |
|---|---|---|---|
| 旧爱重逢 | 结算“他现在是否偏离新基线”或保持沉默 | 自动证明旧情未断 | 六年后两个人如何重新定义彼此 |
| 豪门长辈打压/拿钱逼离开 | 记录某人是否因她违背家族常态、提供有限现实窗口 | 让系统替她赢继承权或强迫家族接受 | 谁愿意承担公开站队后的现实代价 |
| 修罗场争夺 | 逐人观测不同选择、突出可比性谬误 | 官方排名、最爱榜、偏航总分 | 她为什么偏偏把某类动作当作爱 |
| 高危救援 | 区分职责行为与额外偏离 | 因场面大自动判高偏航；系统制造事故 | 人物是否尊重她的边界、救完以后如何相处 |
| 嫉妒/吃醋 | 只在行为真正偏离基线时结算 | 读取内心嫉妒值、自动放大占有欲 | 他怎么处理嫉妒而不剥夺她自由 |
| 舆论爆炸/身份曝光 | P1/P2/P7只处理已有真实信息的顺序、显著性、留存 | 删除事实、制造公众共识、洗掉反证 | 谁愿意公开承担自己的版本 |
| 误会/背叛 | 新证据进入后修正旧判断 | 系统提前告诉她“谁是真凶/谁没背叛” | 她基于不完整信息做过的伤害如何修复 |
| 家族联姻/利益婚约 | 观察人物是否偏离长期责任/利益轨迹 | 系统替人物解除法律、资本、家族约束 | 自由选择与现实义务怎样同时存在 |
| 失踪六年真相 | 只处理当下人物因她发生的新偏离 | 回放六年、补失踪证据、解码LQ-17 | 现实证据链和她本人记忆如何重新拼起来 |
| “所有人都选她”的大场面 | 分别判断真实个体选择，必要时系统大部分沉默 | 群体偏航、天选认证、主角光环数值化 | 同时被很多人选择反而逼她决定自己要什么 |

### 转译原则

- 狗血强度来自**人物愿意承担什么后果**，不是协议愿意给多大权限。
- 越是高强度桥段，越要检查系统是否可以少说一句；如果现实人物已经足够失控，系统应退后。
- 所有“协议帮助女主赢”的桥段都必须改写成“协议让她看见一个有限结构，她仍然可能输”。
- 当系统提示会削弱羞耻、嫉妒、愤怒、后悔、失望或爱本身时，优先删提示。

**APP-010验收句**：最狗血的场面也必须先是人的灾难，再是系统的观测对象。

## APP-011｜关系生命周期调用矩阵：同一句“偏航成立”，在不同关系阶段绝不能承担同一种意义

协议只判断人物相对自身基线的改变，因此**关系阶段决定叙事解释空间，不改变系统判定标准**。生产时先锁定关系所处阶段，再决定系统应显性、沉默还是只承担修正功能。

| 关系阶段 | 协议最适合承担的功能 | 黎栖雾最容易出现的误读 | 正文真正要推进的关系问题 |
|---|---|---|---|
| 初识/陌生 | 多数情况下保持沉默；若基线不足就明确`BASELINE_UNCERTAIN` | 把一次反常举动直接解释成“他对我特殊” | 为什么这个人愿意靠近、保持距离或改变原计划 |
| 旧识/旧爱重逢 | 比较“现在的他”与新人生基线，而不是拿六年前旧基线无限复用 | 把旧情历史当成当前爱情自动续费 | 六年空白之后，两个人是否还愿意重新认识彼此 |
| 暧昧/试探 | 适合观测少量真实偏离，同时保留大量沉默 | 把频繁触发当成关系确认 | 谁先承认欲望、谁保留退出权、谁在用测试替代表达 |
| 热烈靠近期 | 高偏航样本可能增多，但同源动作开始衰减 | 把“越失控越爱”当成真理 | 强烈吸引能否转化为边界、修复和互惠 |
| 稳定关系 | 系统应明显减少存在感，动态基线吸收大量旧动作 | 把沉默误读成降温或不再重要 | 低刺激日常里是否仍有持续选择与自我完整性 |
| 冷战/破裂 | 可观测退出、拒绝、克制、报复等偏离，但不裁判谁更爱谁 | 把高成本痛苦行为当成复合资格 | 伤害是否能被承认、修复是否被允许、边界是否重建 |
| 分手/分离 | 系统可以确认“离开本身是否偏离”，但不能把离开解释成反向深情 | 认为“他越痛苦地走，越证明舍不得我” | 两个人是否有权不再继续，以及分开之后各自如何活 |
| 复合/重建 | 优先看新的低刺激持续性，不奖励重复旧戏码 | 用一次巨大偏航覆盖旧问题 | 新关系是否真的换了结构，而不是回到原有循环 |
| 长期伴侣/终局 | 系统存在感降到最低，只保留极少结构节点与长期模型诱惑 | 把可预测性当成永久安全 | 她是否愿意在没有最终证明的情况下继续选择 |

### 生产纪律

- 同一个男主跨阶段时，**基线必须更新**。早期高偏航行为进入长期日常后，不能持续当成高价值新证据。
- 分手、拒绝、退出、保持距离都可能构成偏航；“靠近”没有天然更高叙事权。
- 复合章节禁止用“系统再次响了”作为复合成立证据。复合成立必须落在现实修复、重新协商和持续行为。
- 旧爱线最危险的偷懒是把“六年前爱过”直接当成当前基线真值；生产时必须明确**旧历史只提供背景，不替当前关系作答**。

**APP-011验收句**：协议判断的是他改变了什么，关系阶段决定这个改变现在意味着什么问题。

## APP-012｜系统沉默的叙事功能库：没有提示也必须能形成戏，而不是留白

`SYSTEM_SILENT`不是“什么都没发生”，而是作者主动决定**这场关系变化不需要系统解释**。沉默场景应至少承担以下一种功能。

### 六类有效沉默

1. **基线沉默**：人物长期稳定地做同一件事，行为已经成为新基线。适合霍岑式可靠、闻惟止式边界、顾砚秋式等待等长期模式。重点写“仍然在做”，而不是“系统为什么没响”。
2. **证据沉默**：行为很抓人，但四门或因果证据不足。读者可以猜，黎栖雾也可以误读，系统不抢先定性。
3. **成熟沉默**：关系已经不需要每次改变都被认证。人物在低刺激场景里互相照顾、争执、修复、让步，系统不出现反而证明叙事解释权回到人手里。
4. **伦理沉默**：系统虽然存在，但涉及隐私、第三方权利、非法信息、受保护判断或无合法窗口时保持边界。这里的沉默强化世界规则，不是削弱系统。
5. **拒绝沉默**：黎栖雾主动不查询、不接受窗口或不继续观测。她必须在不知道答案的情况下作决定。
6. **高潮沉默**：人物已经做出足够强的现实选择，任何提示都会降低羞耻、痛苦、嫉妒、告白、背叛或离开的冲击，因此系统退场。

### 沉默场景的三种写法

- **让黎栖雾注意到沉默**：适合她仍依赖系统的阶段。“为什么没响”成为她自己的不安，但系统不回应。
- **让读者注意到沉默**：前几卷建立过系统语法后，读者预期提示却没有提示，从而主动开始用现实行为判断关系。
- **让任何人都不注意到沉默**：中后期成熟写法。系统真实存在，但正文已经不需要提醒读者它没有出现。

### 禁止补偿

- 不因为连续多场沉默就在下一场塞一个“补发偏航”。
- 不用作者旁白解释“虽然系统没响，但他其实更爱”。
- 不把沉默写成系统掉线、冷却、惩罚、能量不足，除非上位正史未来明确新增此类机制。

**APP-012验收句**：最成熟的系统场景之一，就是系统什么都没说，而人物仍然完成了关系变化。

## APP-013｜五层信息差与POV编译：后台知道、黎栖雾知道、对方知道、第三方知道、读者知道必须分开

本节把SYS-P013编译为正文可直接使用的信息差工具。任何协议场景至少先标记五层可见性：

`BACKEND / HOST / TARGET / THIRD_PARTY / READER`

### 五层生产权限

- **BACKEND**：协议内部能够用于结算的有限结构信息。后台“能验证”不等于可以整段展示给黎栖雾。
- **HOST**：黎栖雾当前真正看到的最小提示、窗口边界与自己现实掌握的信息。她不能访问完整人物档案、隐藏动机或后台审计链。
- **TARGET**：被观测的人默认不知道系统结论。他可以知道自己的选择、她的试探、被设计的节点，除非经过明确披露，否则不知道协议UI或后台。
- **THIRD_PARTY**：旁人只能根据现实行为、关系和公开信息判断。系统提示不能自动变成宴会、家族、媒体或朋友圈都知道的事实。
- **READER**：读者通常通过黎栖雾POV看到HOST层，但作者可以让读者额外看到目标人物的动作、迟到证据或第三方反应，从而形成“读者知道她误读了”的戏剧反讽。

### 四种高价值信息差结构

1. **HOST领先**：黎栖雾知道“偏航成立”，目标人物不知道她拥有这一判断。适合制造她的隐秘自信或误读。
2. **TARGET领先**：对方知道自己为什么这么做，黎栖雾只有系统结论却不知道完整动机。适合证明系统正确但不完整。
3. **READER领先**：读者已经看到一个低刺激成熟行为或反证，黎栖雾仍沉迷于高偏航样本。适合加强她的盲点而不靠旁白说教。
4. **HOST误领先**：她以为自己因为系统“知道更多”，实际上只知道变化是否发生，不知道关系意义。适合中段反噬。

### POV硬规则

- 系统提示不能作为全知旁白许可。写男主内心时仍服从当前POV规则，不能因为系统存在就偷读心。
- 读者知道得更多时，必须来自**现实可见动作、合法POV切换或迟到证据**，不能来自作者把后台数据库直接倒出来。
- 披露协议后，TARGET层增加的是“知道协议存在/知道被测量”，不是自动升级为HOST层权限。

**APP-013验收句**：信息差越大，越要清楚谁真正知道什么；系统不是全知叙事许可证。

## APP-014｜白噪×偏航协议双轨生产模型：一个负责现实研判，一个负责有限偏航观测，二者必须允许互相不一致

白噪是黎栖雾的现实分析能力，偏航协议是唯一超自然层。两者同场时采用`DUAL_TRACK_ANALYSIS`，禁止融合成“超级AI”。

### 双轨分工

| 维度 | 白噪 | 偏航协议 |
|---|---|---|
| 输入 | 现实数据、文件、访谈、市场/风险信号、公开或合法获取的信息 | 合格人物事件、个人基线、偏离、因果、成本、有限现实窗口 |
| 优势 | 能做复杂现实推理、比较方案、识别系统性风险 | 能稳定确认某些“因她而改变”的行为结构 |
| 盲区 | 数据可能不完整、模型可能错、对人的情感意义只能推断 | 不理解爱情质量、不读心、不替代调查/医学/法律/金融判断 |
| 输出 | 风险区间、方案、解释、假设、证据权重 | 最小状态、有限窗口、修正或沉默 |
| 责任 | 黎栖雾必须承担模型选择与现实执行责任 | 黎栖雾必须承担是否查询/授权以及介入后的现实后果 |

### 四种可写冲突

1. **白噪认为合理，协议无偏航**：人物行为完全符合职责和利益结构。她必须接受“对我有利”不等于“因为我改变”。
2. **协议确认偏航，白噪认为关系风险仍高**：一个人为她改了很多，但风险模型显示边界、治理、声誉、法律或长期稳定性很差。最适合打破“偏航=好关系”。
3. **白噪判断低风险，协议却出现异常偏离**：现实模型认为局面稳定，但某个人突然作出超出自身基线的选择，迫使她重新理解这个人，而不是自动改模型结论。
4. **两者都不确定**：这是必须保留的合法状态。不能为了剧情顺滑让系统替白噪补数据，也不能让白噪用概率模型伪造系统结论。

### 同场写法

- 先明确这场戏问的是**现实问题**还是**人物偏航问题**；现实问题由白噪/职业体系主导，偏航问题由协议主导。
- 如果两个体系给出不同答案，**保留冲突**，不要让其中一个弹窗宣布另一个错了。
- 白噪可以让黎栖雾觉得自己“已经算得很清楚”，协议可以让她看见一个人偏离模型；但关系意义仍然要由现实互动解释。

**APP-014验收句**：白噪告诉她世界怎么走，协议告诉她某个人有没有因为她改道；没有任何一个替她回答“该不该爱”。

## APP-015｜系统场景去同质化与去游戏化审计：长期连载不能反复“动作—弹窗—震惊”

每次准备连续写第二个以上系统场景时，执行`PROTOCOL_VARIATION_AUDIT`。目标不是增加花样权限，而是**更换叙事承载方式**。

### 十个可轮换变量

1. **主体位置**：她在场看见 / 她事后得知 / 她只看到后果。
2. **结算时机**：动作后立即 / 证据成熟后 / 跨场景迟到修正。
3. **前台可见度**：明确一句 / 极短边界提示 / 完全沉默。
4. **关系方向**：靠近 / 拒绝 / 退出 / 等待 / 克制 / 公开承担 / 私下修复。
5. **现实成本类型**：时间、机会、声誉、资源、关系、原则摩擦、身份暴露，避免总写“砸钱/冒险”。
6. **信息结构**：她领先 / 对方领先 / 读者领先 / 所有人都只知道一部分。
7. **系统功能**：观测 / 窗口 / 拒绝 / 修正 / 终局诱惑；普通章节不要连续重复同一类。
8. **情绪结果**：爽、难堪、失望、嫉妒、心软、愤怒、怀疑、后悔，不让“偏航成立”永远只对应心动。
9. **下游结果**：成功 / 失败 / 关系恶化 / 现实无结果但认知变化 / 新证据推翻旧解释。
10. **是否出现系统**：最重要的轮换项。真正成熟的节奏必须允许连续多个关键场景完全没有系统前台。

### 三条反游戏化硬闸

- 禁止形成“刷偏航—升级HOST_CAP—开更高P级—获得更大剧情奖励”的爽游闭环。
- 禁止把窗口、提示、事件簇写成物品栏、任务列表、成就徽章或可累计数值。
- 禁止让每个男主都拥有一个固定“触发套路”；人物差异来自人生基线和选择，不来自系统职业技能树。

### 连续章节审计

若最近三次系统出场中出现以下任一重复，下一次优先`SYSTEM_SILENT`或更换现实承载：
- 三次都以`【偏航成立。】`收尾；
- 三次都是男主做巨大牺牲；
- 三次都是黎栖雾先看系统再决定怎么对待人；
- 三次都靠系统制造章尾悬念；
- 三次都没有产生新的现实后果，只增加“他又为她偏航了”的确认感。

**APP-015验收句**：系统越稳定，写法越不能稳定成一个模板。
