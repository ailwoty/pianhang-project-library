### TYPE枚举与字段适用性
`TYPE`只允许：
- `CHAPTER`：某个`CHAPTER_UID`第一次进入正式正史的章节提交；
- `CHAPTER_REVISION`：同一`CHAPTER_UID`后续正式修订提交；仍产生本R###独立BODY/DELTA与RESULT_SNAPSHOT，并通过`SUPERSEDES_COMMIT_ID`指向被替代的有效`COMMITTED`章节事务；
- `CANON_BASELINE`：`CM_BASE_<TOPIC>_R###`。只把用户明确确认或既有上位硬正史逐命题锁定、且发生在当前故事T0之前、此前尚未COMMITTED的新历史基线编译为`S0_WORLD_LOCK / TRUE_CANON` FACT/EVT。不得修改已有COMMITTED真值，不得生成章节BODY/DELTA，不得推进WORLD_CLOCK，不得进入正式正文索引，也不得成为项目级故事`CURRENT_COMMIT_ID`；
- `MAINTENANCE`：`CM_MAINT_<TOPIC>_R###`治理/登记/缓存/来源修复。它可以修正schema、provenance、索引或“记录错误但故事事实不变”的运行登记，但**不得制造或改变客观故事FACT/EVT真值，不得推进WORLD_CLOCK，不得生成章节BODY/DELTA，不得进入正式正文索引，也不得成为项目级故事`CURRENT_COMMIT_ID`**。

字段矩阵：
- `CHAPTER/CHAPTER_REVISION`：`CHAPTER_UID / BASE_SNAPSHOT_ID / RESULT_SNAPSHOT_ID / WORLD_CLOCK_START / WORLD_CLOCK_END / CANON_INDEX_VERIFY / CURRENT_SNAPSHOT_VERIFY`均为必填并参与章节正史激活；`LOCAL_TEMP_REF_MAP`在首次PREPARED行必填并携带`LOCAL_TEMP_SCOPE`（无新TMP仍保留scope并写`NONE_NO_NEW_TEMP_REFS`），`PREPARED_PAYLOAD_FINGERPRINT`同样必填并冻结本R###语义载荷；如创建新稳定ID/局部revision，`ID_ALLOCATION_MANIFEST`必须先于目标写入完成持久登记且逐项回指scope+TEMP_REF；
- `CANON_BASELINE`：`CHAPTER_UID / BASE_SNAPSHOT_ID / RESULT_SNAPSHOT_ID / WORLD_CLOCK_START / WORLD_CLOCK_END = N_A`；`LOCAL_TEMP_SCOPE=BASELINE_<LOCAL_TOKEN>`、`LOCAL_TEMP_REF_MAP`、`PREPARED_PAYLOAD_FINGERPRINT`、`ID_ALLOCATION_MANIFEST`均按章节级严格度执行；`PREFLIGHT_IMPACT`固定`INVALIDATES`；`CANON_INDEX_VERIFY`验证S0 FACT/EVT与来源闭合，`CURRENT_SNAPSHOT_VERIFY`验证R003章节CURRENT四元组完全不变；
- `MAINTENANCE`：上述章节/快照推进字段、`LOCAL_TEMP_REF_MAP`与`PREPARED_PAYLOAD_FINGERPRINT`统一写`N_A`，使用`PREFLIGHT_IMPACT / TARGET_MANIFEST / CONCURRENCY_MODE / STATUS / FAILED_TARGETS / RECOVERY_COUNT / COMMIT_FINALIZED_AT`及必要的重试字段；若维护需要读取当前故事状态，只作为只读前置条件，不把它登记成BASE→RESULT故事快照链；
- `MAINTENANCE`若修改当前快照文件，只允许治理元数据或把**已经COMMITTED的故事CURRENT**做等价物化/缓存整理；VERIFY必须证明`EFFECTIVE_CURRENT_SNAPSHOT_ID / CURRENT_COMMIT_ID / WORLD_CLOCK_CURSOR / LAST_COMMITTED_CHAPTER_UID`逻辑值未改变。
- 每个`MAINTENANCE`必须在独立列`PREFLIGHT_IMPACT`填写`INVALIDATES / NEUTRAL_RECORDER`；每个`CANON_BASELINE`必须固定填写`INVALIDATES`。`TARGET_MANIFEST`可重复说明但不得作为唯一机器来源。

若一项工作需要新建T0前历史FACT/EVT真值：只有命题已达到A0_USER或等价既有硬正史来源、且不是对既有COMMITTED真值的修订时，才允许`CANON_BASELINE`。普通候选、T0后故事事实、已有真值修订、世界时钟推进或正式正文替换，必须改走`CHAPTER/CHAPTER_REVISION`及相应RETCON Gate；禁止借`MAINTENANCE`或`CANON_BASELINE`绕开正史授权。

`RESULT_SNAPSHOT_ID`必须在PREPARE时确定，章节事务格式为`SNAP_<CHAPTER_UID>_R###`并与COMMIT的R###一致；它与`BASE_SNAPSHOT_ID`共同证明状态从哪一版演化到哪一版。
`CURRENT_SNAPSHOT_VERIFY`验证当前快照寄存器保留BASE且写入匹配的PREPARED候选；事务COMMITTED后，有效CURRENT由事务日志派生为RESULT_SNAPSHOT_ID，不要求再做一次必要快照覆盖。
`PREVIOUS_ATTEMPT_COMMIT_ID`只用于同一逻辑工作在上一独立事务已`ABORTED`后新建R###重试；它引用失败尝试，不表示正史替代。
`SUPERSEDES_COMMIT_ID`只用于本事务成功后替代一条历史`COMMITTED`正史提交；不得指向PREPARED/PARTIAL_FAILURE/ABORTED。二者可以同时存在：例如R002尝试失败后R003重试，同时R003仍要替代既有R001正史。

状态值：
- PREPARED
- PARTIAL_FAILURE
- COMMITTED
- ABORTED

状态规则：
1. `PARTIAL_FAILURE`不是正史；只有载荷完全不变且基准重新验证后，才允许在同一COMMIT继续补写并最终转COMMITTED。
2. `ABORTED`是终态，永远不能再转COMMITTED；语义变更后必须新建同CHAPTER_UID的下一`R###`。
3. `COMMITTED`只在所有目标回读通过后最后写入；一旦COMMITTED即永久保持COMMITTED，证明该载荷在历史上确实正式生效过。
4. 后续正式修订成功时，不修改旧COMMIT的STATUS；由**新的COMMITTED事务**填写`SUPERSEDES_COMMIT_ID`指向旧COMMIT。某COMMIT是否仍为“有效当前”由后继替代链派生，而不是把旧COMMITTED改写成SUPERSEDED。
