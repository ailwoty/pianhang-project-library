# V12正文运行态｜资源流量与稀缺周期 V5

状态：ACTIVE
SCHEMA_VERSION：5

## 目的
补足系统90中的“自然产出、消耗、折旧、稀缺、替代”，避免资源账只有静态存量。

## FLOW字段
FLOW_ID / FLOW_REVISION / RESOURCE_ID / OWNER_ID / FLOW_TYPE / RATE_OR_AMOUNT_MODEL / START_WORLD_CLOCK / END_WORLD_CLOCK / WALL_CLOCK_START_LOCAL(optional) / WALL_CLOCK_END_LOCAL(optional) / INPUT_RESOURCE_IDS / OUTPUT_RESOURCE_IDS / TRIGGER_FACT_IDS / TRIGGER_EVENT_IDS / MAINTENANCE / DEPRECIATION / BOTTLENECK / SUBSTITUTE_RESOURCE_IDS / SAFETY_BUFFER / CURRENT_STATE / LAST_CHANGED_BY_COMMIT_ID

- `FLOW_ID`格式：`FLOW_######`；`FLOW_REVISION`是单个FLOW内部局部正整数版本，建立时=1，持久状态/速率/瓶颈等变化时递增。
- `RESOURCE_ID`、`INPUT_RESOURCE_IDS/OUTPUT_RESOURCE_IDS/SUBSTITUTE_RESOURCE_IDS`只引用`RES_*`；`OWNER_ID`引用既有实体ID，不新建“OWNER”命名空间。
- `START_WORLD_CLOCK/END_WORLD_CLOCK`只表示故事世界顺序，使用`D<RELATIVE_DAY>.S<ORDER_ORDINAL>`或UNKNOWN；不得写宿主机/Library/事务终结时间。精确故事本地钟点没有来源时`WALL_CLOCK_*_LOCAL=UNKNOWN`；事务物理时间只查`COMMIT_FINALIZED_AT`。
- `RATE_OR_AMOUNT_MODEL`只描述流量/数量/频率模型；触发原因只写`TRIGGER_FACT_IDS/TRIGGER_EVENT_IDS`，不再把“速率或触发”混在同一字段。
- `TRIGGER_FACT_IDS/TRIGGER_EVENT_IDS`用于证明该FLOW为何启动/变化；资源流账不自行复制客观事实。
- `LAST_CHANGED_BY_COMMIT_ID`决定该FLOW当前revision何时正式生效；事务未COMMITTED的FLOW变化不得被下一章读取为CURRENT。

FLOW_TYPE：
PRODUCTION / REPLENISHMENT / CONSUMPTION / MAINTENANCE / DEPRECIATION / TRANSFER / LOCKUP / RELEASE。

## 运行
每个MESO周期检查：
- 核心资源是否需要维护
- 资源是否因事件锁定/释放
- 是否出现瓶颈
- 是否存在替代
- 是否产生真实冲突

## 禁止
- 不为了制造冲突把所有资源突然写成短缺。
- 公共权力/军务/司法/监管权限不是可套利商品。
- “套利”只保留合法/合规或叙事层面的资源价差和配置差，不提供违法金融操作。
