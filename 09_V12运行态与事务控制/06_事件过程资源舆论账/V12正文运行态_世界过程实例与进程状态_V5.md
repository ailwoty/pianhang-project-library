# V12正文运行态｜世界过程实例与进程状态 V5

状态：ACTIVE
SCHEMA_VERSION：5

## 1. 定位

本文件是V12既有动态世界引擎（尤其7I.87世界独立时间推进）与当前`PROC_######`命名空间的**运行实例账**，不是新增系统。

`PROCESS_FAMILY_*`只表示持续运行领域/过程家族；只有具体主体、状态、时间窗口与来源链足够区分时，才创建`PROC_######`实例。

世界过程 ≠ 世界事件：
- PROCESS描述持续运行、推进、维护、积累或衰减的状态链；
- EVENT描述达到可区分发生点/后果的事件节点；
- PROCESS可以产出EVENT候选，但不能用“进程存在”偷渡“事件已经发生”。

## 2. PROC字段

每个持久过程实例：
- PROC_ID：`PROC_######`
- PROC_REVISION
- PROCESS_FAMILY
- PROCESS_SCOPE：PERSONAL / PROFESSIONAL / ORGANIZATIONAL / PUBLIC_INSTITUTION / WORLD
- SUBJECT_IDS：人物/组织等已登记实体
- REGION_IDS：涉及地域；未知可为空/UNKNOWN
- CURRENT_STATE：ACTIVE / HOLD / CLOSED
- STORY_STATUS：S2_RUNTIME_PREMISE / S6_CANDIDATE / S1B_OCCURRED_OFFSCREEN / S1A_OCCURRED_ONPAGE（按实际成立方式）
- TRUTH_STATE：TRUE_CANON / UNKNOWN / UNOBSERVED / NOT_COMMITTED / DISPUTED / SUBJECTIVE（按真值模型）
- START_WORLD_CLOCK：`D<RELATIVE_DAY>.S<ORDER_ORDINAL>`或UNKNOWN
- LAST_ADVANCED_WORLD_CLOCK：`D<RELATIVE_DAY>.S<ORDER_ORDINAL>`或UNKNOWN
- WALL_CLOCK_START_LOCAL：可选；无权威来源时UNKNOWN
- WALL_CLOCK_LAST_ADVANCED_LOCAL：可选；无权威来源时UNKNOWN
- SIM_PRECISION_LEVEL：P0_DORMANT / P1_COMPRESSED / P2_TRACKED / P3_FINE / P4_SCENE_SYNC
- NEXT_CHECK
- DRIVER_OR_GOAL
- CONSTRAINTS
- SOURCE_FACT_IDS：具体`FACT_######_v#`
- PARENT_PROCESS_IDS：已有`PROC_*`；无则NONE
- RESOURCE_DEPENDENCY_IDS：`RES_*`/`FLOW_*`等已登记引用
- INFO_DEPENDENCY_IDS：`INFO_*`/`CLAIM_*`/`KNOW_*`等已登记引用
- CURRENT_OUTPUT_REFS：只引用已存在或同事务创建的FACT/EVT/INFO/NAR/CAUS/RES/FLOW等节点；不得在本字段复制事实本体
- MAJOR_NODE_RISK
- LAST_CHANGED_BY_COMMIT_ID

## 3. 实例化门槛

只有至少能回答以下问题时才分配`PROC_ID`：
1. 谁/什么主体在运行；
2. 属于哪个PROCESS_FAMILY；
3. 当前状态或推进窗口是什么；
4. 来源来自哪条已知FACT、既有PROCESS、母版运行前提或合法PRE_SIM输入；
5. 为什么不是为了让角色“刚好有空/刚好出事”而临时制造。

无法回答时：
`UNKNOWN / UNINSTANTIATED`，不占用`PROC_ID`。

## 4. 生命周期

允许：
- 实例化 → ACTIVE
- ACTIVE → HOLD → ACTIVE
- ACTIVE/HOLD → CLOSED

规则：
- HOLD必须有真实阻塞原因与`NEXT_CHECK`；
- CLOSED必须保留关闭原因/输出引用，不物理删除PROC_ID；
- 已关闭进程若出现新的独立目标/主体/因果链，创建新PROC，不复活旧ID伪装成同一进程；
- `CURRENT_STATE`不单独证明故事事实；正史效力仍服从`STORY_STATUS/TRUTH_STATE + COMMIT_ID`。

## 5. 与世界时钟和精度控制的关系

- MICRO相关过程可在场景级推进；MESO/MACRO过程按系统87与精度控制器压缩更新。
- 远端低关联过程只保留关键状态变化与结果引用，不展开无收益场景。
- `LAST_ADVANCED_WORLD_CLOCK`表示最近一次有审计意义的过程推进，不要求每个虚拟时刻都写记录。
- `START_WORLD_CLOCK/LAST_ADVANCED_WORLD_CLOCK/NEXT_CHECK`若承载时间，均按故事WORLD_CLOCK_TOKEN/窗口语义解释；不得写宿主机或Library时间。精确钟点没有来源时只写WORLD_CLOCK_TOKEN，`WALL_CLOCK_*_LOCAL=UNKNOWN`，不得为填字段补造。事务物理终结时刻只由事务日志`COMMIT_FINALIZED_AT`承担。
- `SIM_PRECISION_LEVEL`服从世界仿真精度控制器；精度升降只改变模拟粒度，不自动改变PROCESS的真值/故事状态。

## 6. 与16核心人物进程句柄

`V12正文运行态_16核心人物独立进程与可入场条件_V5.md`中的：
- PROFESSIONAL_PROCESS_ID
- PERSONAL_PROCESS_ID

若非UNKNOWN/UNINSTANTIATED，必须引用本账存在的`PROC_*`。
人物句柄只保存“当前挂接哪条过程 + 可用性成本”，过程完整状态以本账为准，禁止双写两套事实。

## 7. 与势力/资源/情报/事件的关系

- 组织状态账可以引用PROC作为`CURRENT_ACTION_REFS`，但组织账不复制PROCESS本体。
- 资源流`FLOW_*`可以作为PROCESS输入/输出，但资源变化仍由资源账维护。
- 情报/舆论变化仍由INFO/NAR账维护。
- PROCESS达到可区分事件点时，可形成`EVT_*`候选；仍需CAUSE_SEEDS、Gate和事务提交。
- 客观事实仍只在FACT/EVENT单一真值源中成立。

## 8. T0

`PROC_RECORDS = NONE_COMMITTED`。

解释：
- 当前已确认的是PROCESS_FAMILY/运行义务，以及“世界与人物不会因离镜停止”的规则；
- 尚未为第一章前的具体职业/私人/组织过程分配正式`PROC_*`实例；
- 这不等于世界待机，也不等于15男主空闲；进入相关PRE_SIM/ENTRY_READINESS时按真实来源实例化必要过程。

禁止为了证明“世界很活”一次性给所有核心人物造PROC。

## 9. 提交规则

- `PROC_REVISION`是单个PROC内部局部正整数版本；实例化=1，推进/HOLD/恢复/关闭或其他持久字段变化时递增。
- 新建/推进/关闭PROC若改变持久运行状态，必须随章节或维护事务写入`LAST_CHANGED_BY_COMMIT_ID`。
- 事务未COMMITTED前，候选PROC变化不得被下一章当CURRENT。
- 没有故事事实变化的纯治理schema修复可使用`CM_MAINT_*`，但不得借维护事务制造新的离屏行动。
