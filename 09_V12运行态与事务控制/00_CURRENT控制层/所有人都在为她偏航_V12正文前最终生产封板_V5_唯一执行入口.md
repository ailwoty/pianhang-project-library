## 7. 事务

正文+状态使用同一COMMIT_ID：
READ_GUARD → LOAD_CONTROL → LOAD_STORY → VALIDATE_INPUT → PRE_SIM → BUILD_PLAN → 7K_RECALL（需要时）→ DRAFT → REVIEW → STAGE_STATE → POST_SIM → GATES/VALIDATE_TRANSACTION → ACQUIRE_WRITE_GUARD/PREPARE → WRITE_TARGETS → VERIFY_TARGETS → FINALIZE_COMMIT_LOG → VERIFY_COMMIT → PUBLISH_SNAPSHOT。

`ACQUIRE_WRITE_GUARD/PREPARE`必须先确认没有其他`PREPARED/PARTIAL_FAILURE`写事务，并把本COMMIT事务日志记录先持久写成PREPARED、回读成功；该非终态记录就是SINGLE_WRITER租约。未取得租约，不得写正文、DELTA、运行账或PREPARED_CANDIDATE。租约直到同一COMMIT终结为不可逆COMMITTED/ABORTED才释放。

章节正文与DELTA不是可被下一事务覆盖的“固定文件槽”，而是每个`CM_<CHAPTER_UID>_R###`各自新建：
- `V12正文_<CHAPTER_UID>_R###.md`
- `V12状态_<CHAPTER_UID>_R###_DELTA.md`
两者落库后以稳定`library_file_id`写入本COMMIT的正文索引候选行；旧COMMITTED BODY/DELTA永不被新PREPARE覆盖。

任何必需写入失败：
章节不FINALIZED；事务日志不得标COMMITTED；候选事实不进入下一章。
事务日志COMMITTED是所有必写目标回读通过后的最后正史开关；`COMMITTED/ABORTED`均为不可逆终态。
若新R###承接上一ABORTED尝试，用`PREVIOUS_ATTEMPT_COMMIT_ID`；若新COMMITTED事务正式替代既有COMMITTED正史，用`SUPERSEDES_COMMIT_ID`。失败尝试链与正史替代链不得混写。
PREPARE同时确定`BASE_SNAPSHOT_ID → RESULT_SNAPSHOT_ID`；其中BASE必须等于事务开始时联查得到的`EFFECTIVE_CURRENT_SNAPSHOT_ID`。当前快照只有一个候选槽：若上一有效CURRENT仍位于旧候选槽，新事务取得写租约后必须在同一次快照写入中先把它压实为新的MATERIALIZED_BASE，再写本事务PREPARED_CANDIDATE。正文索引/滚动计划/checkpoint只写候选记录。所有`*_REVISION`运行节点追加候选revision、禁止覆盖上一有效revision。
COMMITTED后正文/快照/计划/checkpoint/局部revision的有效CURRENT均由事务日志联查派生，不要求最后开关之后再做必要二次覆盖。
稳定ID分配同样服从写租约：DRAFT/STAGE的新候选先建立非稳定`LOCAL_TEMP_SCOPE=WORKING_<LOCAL_TOKEN>`，并只用该scope内的`TMP_*`本地引用；候选身份是`LOCAL_TEMP_SCOPE + TEMP_REF`。若PREPARE前草稿持久化，文件名`WORKING_<LOCAL_TOKEN>`、`LOCAL_CHAPTER_HANDLE=<LOCAL_TOKEN>`与`LOCAL_TEMP_SCOPE`必须逐字同源；scope一旦进入任何PREPARED/终态COMMIT即永久消费，新COMMIT不得复用，ABORT重试与CHAPTER_REVISION都必须fork新scope，只有同一PARTIAL_FAILURE恢复继续原scope。PREPARED日志成功时保留COMMIT R###与首次CHAPTER_UID，并同步保留由二者唯一派生的`RESULT_SNAPSHOT_ID=SNAP_<CHAPTER_UID>_R###`。PREPARED行还必须把`LOCAL_TEMP_SCOPE`与`LOCAL_TEMP_REF_MAP`作为两个独立事务列持久化（无新TMP也保留scope、map显式NONE）；已在任何历史PREPARED/终态COMMIT出现的scope不得被另一COMMIT复用，并对正文+完整staged delta+章节语义元数据+LOCAL_TEMP_SCOPE+LOCAL_TEMP_REF_MAP+目标角色集合持久化`PREPARED_PAYLOAD_FINGERPRINT=SHA256_UTF8_CANONICAL_JSON_PAYLOAD_V2:<hex>`；取得租约后再持久登记`ID_ALLOCATION_MANIFEST`，且只能把同一scope+map中已声明TMP映射为正式稳定ID或BODY/局部revision。ID规则登记的全部稳定命名空间与局部revision槽默认受租约保护，只有COMMIT/首次CHUID/派生RESULT_SNAPSHOT、Library身份、WORKING/TMP本地句柄、LEGACY_ALIAS和纯引用字段等显式例外除外。ABORT已登记编号永久烧号，PARTIAL_FAILURE由同一事务续占；同一逻辑章节重试只继承CHAPTER_UID。
载荷一致性：`PARTIAL_FAILURE`只有在重算`PREPARED_PAYLOAD_FINGERPRINT`与首次PREPARED值完全一致时才能续同一事务；正文、delta、LOCAL_TEMP_SCOPE、TMP图、章节语义元数据或目标角色集合任一变化都必须ABORT并新R###。
事务`TYPE`只允许`CHAPTER / CHAPTER_REVISION / CANON_BASELINE / MAINTENANCE`。`CHAPTER/CHAPTER_REVISION`属于章节故事提交链；`CANON_BASELINE / CM_BASE_*`只把用户/上位硬正史已确认且发生于当前故事T0之前的新历史基线编译为`S0_WORLD_LOCK / TRUE_CANON` FACT/EVT；`MAINTENANCE / CM_MAINT_*`只做治理/登记/缓存/来源修复。后两类均不得产生章节BODY/DELTA、RESULT_SNAPSHOT或世界时钟推进，也不得成为项目级故事`CURRENT_COMMIT_ID`。
