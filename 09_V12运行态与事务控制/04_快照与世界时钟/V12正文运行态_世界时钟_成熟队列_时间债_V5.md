## A. 时间
三层：
- MICRO：场景内先后、等待、信息到达
- MESO：数日—数月，组织/调查/舆论/项目
- MACRO：卷级/时代级变化

### A0. 规范世界时钟
`WORLD_CLOCK_TOKEN`格式：`D<RELATIVE_DAY>.S<ORDER_ORDINAL>`。

当前T0基线：`D0.S0000`。

规则：
1. `D0/D1/...`只表示相对故事日，不自动绑定现实日历日期。
2. `S`只用于同一相对日内的因果/事件先后排序，不表示分钟、秒或持续时长；例如`D0.S1000 < D0.S2000`只证明前者早于后者。
3. 序号采用稀疏分配，便于后续插入同期独立事件；不得把序号差值解释成经过时长。
4. 精确本地钟点与世界顺序分离：仅在母版、已提交正文或可靠来源明确时填写`WALL_CLOCK_LOCAL=HH:MM[:SS]`；否则为`UNKNOWN`。
5. 第一章即使精确钟点保持UNKNOWN，也可以使用`WORLD_CLOCK_START/END`完成事务排序，不得为了填字段复活07:30/07:52。
6. 旧`D0_START`只作`LEGACY_TIME_ALIAS → D0.S0000`读取；新记录禁止继续写`D0_START`。

重要时间字段（P425统一语义）：
- 故事运行账中的`OCCURRED_AT / OBSERVED_AT / DISCOVERED_AT / ACQUIRED_AT / MADE_AT / CREATED_AT / UPDATED_AT / RECORDED_AT`统一承载**故事世界顺序**：值必须是`WORLD_CLOCK_TOKEN`或`UNKNOWN`；不得写宿主机时间、Library修改时间或事务终结时间。
- `RECORDED_AT`表示“该故事记录在世界状态链上被登记/可被后续状态读取的故事时点”，不是物理文件写入时间；物理事务审计时间只由事务日志`COMMIT_FINALIZED_AT`承担。
- 若某故事时点同时有可靠的精确本地钟点，另写相应`*_WALL_CLOCK_LOCAL=HH:MM[:SS]`；没有明确来源就`UNKNOWN`，不得从WORLD_CLOCK序号反推分钟。
- 名称已显式含`*_WORLD_CLOCK / *_WORLD_CLOCK_WINDOW`的字段同样只表示故事顺序/窗口；它们与宿主机wall-clock永久分离。

### 队列引用规则
- `QUEUE_REVISION`是单个Q节点内部局部正整数版本；建立=1，成熟状态/依赖/窗口/检查点等持久变化时递增。
- `VARIABLE_REF_ID`必须指向已存在的稳定节点，例如`FSW_* / PROC_* / RES_* / NAR_* / EVT_* / CAUS_* / ISS_*`等已登记ID；`VARIABLE_REF_TYPE`声明其真实节点类型。
- “合同/调查/联盟”等TYPE只是队列用途分类；若项目尚未为该对象建立可引用的稳定节点，就不得为了入队临时造一个无来源ID，可先挂到已有`PROC_*`或`ISS_*`，或保持未实例化。
- `DEPENDENCIES`同样只引用已存在节点/队列ID，不使用自然语言名称冒充外键。

### 成熟状态机
正常推进：`DORMANT → GROWING → READY → CLOSED`。
- `DORMANT`：已登记但成熟条件尚未开始满足。
- `GROWING`：依赖/时间/因果正在积累。
- `READY`：成熟条件已满足，**只表示可被PRE_SIM/章节计划评估**；不自动改变`STORY_STATUS/TRUTH_STATE`，不自动创建FACT/EVENT，也不强迫当前章节使用。
- `HOLD`：因重大节点、依赖冲突、权限/证据不足等暂停；必须记录`PRE_HOLD_STATE`和原因，解除后回到可证明的前一状态，不默认跳READY。
- `CLOSED`：已兑现、取消、被更高权威废止或被正式替代；必须记录`CLOSE_REASON`。

任何`READY → S1A/S1B`仍必须经过模拟/正文、Gate、事务COMMIT；成熟度本身不是故事发生。

T0：无已提交READY项。09-A仅为开放历史问题，不因主角需要自动成熟。

## C. 时间债
用于“客观已发生但叙事尚未展示”的变化。只有已经成立的FACT/EVENT才能产生时间债，S3/S6候选不能借“时间债”偷渡成既成事实。

字段：
- TIME_DEBT_ID：`TD_######`
- TIME_DEBT_REVISION
- SOURCE_REF_TYPE：FACT / EVENT
- SOURCE_REF_ID：具体`FACT_######_v#`或`EVT_######`
- OCCURRED_AT：规范WORLD_CLOCK_TOKEN或可映射时间
- WHY_NOT_SHOWN
- EXPECTED_KNOWLEDGE_HOLDER_IDS：可合理应知的具体实体；未知可为空
- EXPECTED_KNOWLEDGE_SCOPE：PUBLIC / ORG / RELATION / OTHER / UNKNOWN
- DISCLOSURE_FAIRNESS
- DUE_WORLD_CLOCK_WINDOW：WORLD_CLOCK范围/条件
- TIME_DEBT_STATUS：OPEN / DUE / HOLD / CLOSED
- HOLD_REASON（仅HOLD时）
- LAST_CHANGED_BY_COMMIT_ID
- CLOSE_REASON（仅CLOSED时）

规则：
- `TIME_DEBT_REVISION`是单个TD节点内部局部正整数版本；建立=1，DUE/HOLD/CLOSED、应知范围或披露窗口等持久变化时递增。
- `SOURCE_REF_TYPE + SOURCE_REF_ID`是类型化引用，只允许指向已提交/已确认成立的具体FACT或EVENT；不得引用S3计划、S6候选或未提交节点。
- `EXPECTED_KNOWLEDGE_HOLDER_IDS`只引用实体注册表；没有可具体识别对象时使用`EXPECTED_KNOWLEDGE_SCOPE`，不得临时造“公众ID/知情人ID”。
- `DUE_WORLD_CLOCK_WINDOW`使用相对世界时钟窗口/条件，不以现实日期或无来源钟点替代。
- `DUE`表示公平披露/发现机制已到必须处理的窗口，不等于作者必须立刻揭晓全部真相，更不等于角色自动知道。
- `HOLD`必须有可审计原因，不能无限期隐藏主角合理必然知道的公开重大事件。
- `CLOSED`表示该时间债已经通过展示、发现、合法延后结算或被正式修订处理；必须保留关闭原因。

禁止把晚披露写成晚发生。
禁止隐藏主角合理必然知道的公开重大事件。
