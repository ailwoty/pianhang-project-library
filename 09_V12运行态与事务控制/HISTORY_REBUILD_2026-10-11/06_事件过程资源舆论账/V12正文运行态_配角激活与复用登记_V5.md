# V12正文运行态｜配角激活与复用登记 V5

状态：ACTIVE
SCHEMA_VERSION：5

## 原则
120名历史配角库是候选人物资产，不是120人已全部在当前世界前台激活。
功能角色也不应每章临时新造，优先检查是否已有兼容配角可承担。

## 激活流程
1. 先定义SCENE_FUNCTION。
2. 查询V6_09与后续母版是否有兼容人物。
3. 检查旧职业/身份是否与V12冲突。
4. 若兼容：建立CURRENT_ENTITY_BINDING。
5. 若不兼容：只取人格机制，不复活冲突身份。
6. 若无适合者：使用ROLE_TEMP，必要时后续命名。

## 字段
CAST_BINDING_ID / CAST_BINDING_REVISION / BINDING_STATUS / HISTORICAL_SOURCE_LIBRARY_FILE_ID / HISTORICAL_SOURCE_ANCHOR / CURRENT_ENTITY_ID / FUNCTION / COMPATIBILITY / CURRENT_ORG_ID / CURRENT_ROLE / FIRST_ONPAGE_CHAPTER_UID / INDEPENDENT_GOAL / LAST_USED_CHAPTER_UID / REPETITION_RISK / LAST_CHANGED_BY_COMMIT_ID

- `CAST_BINDING_ID`格式：`CAST_######`，标识一次“历史候选→当前实体/临时角色”的绑定记录；`CAST_BINDING_REVISION`是该绑定内部局部正整数版本，建立=1，改绑/正式命名/组织或角色变化时递增。
- `CURRENT_ENTITY_ID`不是新命名空间；必须引用实体注册表中的`CHR_*`人物实体，或显式的`ROLE_*`临时角色；组织归属单独写`CURRENT_ORG_ID=ORG_*`。
- `FIRST_ONPAGE_CHAPTER_UID/LAST_USED_CHAPTER_UID`使用不可变`CHUID_*`，不得用展示章号作长期外键。
- `HISTORICAL_SOURCE_LIBRARY_FILE_ID + HISTORICAL_SOURCE_ANCHOR`冻结候选来源；不能只写易漂移文件名。
- `LAST_CHANGED_BY_COMMIT_ID`记录绑定/改绑/正式命名等持久变化；事务未COMMITTED前不得把候选绑定当CURRENT实体关系。
