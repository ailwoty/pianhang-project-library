# V12正文运行态｜全局事件总线运行映射 V5

状态：ACTIVE
SCHEMA_VERSION：5

## 目的
把V10/V11/V12已有事件总线落成可追踪映射；不新增系统。

## 事件类型
STORY_EVENT：
人物选择、关系权限变化、资源变化、情报产生、舆论变化、地域进入、危机、伏笔成熟、因果到期。

WORLD_EVENT：
系统87—94产生/提交的世界事件。

META_EVENT：
指标下降、链路异常、规则候选、回滚、知识缺口、熔断等。
META_EVENT永不广播给世界内人物。

## 总线记录
BUS_EVENT_ID / CLASS / SOURCE_REF_TYPE / SOURCE_ID / WORLD_CLOCK_AT / WALL_CLOCK_LOCAL(optional) / PAYLOAD_REFS / PAYLOAD_SUMMARY(optional) / RELEVANT_SUBSYSTEMS / MAX_CASCADE / DELAY / PERMISSION / FUSE / SETTLED_BY_COMMIT_ID / SUPERSEDES_BUS_EVENT_ID。

- `BUS_EVENT_ID`格式：`BUS_######`，只标识“总线上的一次路由记录”，不得与`EVT_######`世界事件混用。
- `SOURCE_REF_TYPE + SOURCE_ID`组成类型化来源引用：必须指向已存在或同事务创建的FACT/EVT/PROC/REL/INFO/NAR/CAUS/HOOK等规范节点，不自成命名空间。
- `PAYLOAD_REFS`只引用已登记节点/记录；`PAYLOAD_SUMMARY`只作路由说明，不能单独制造事实、知识或状态。
- `WORLD_CLOCK_AT`使用`D<RELATIVE_DAY>.S<ORDER_ORDINAL>`；精确钟点若没有权威来源，`WALL_CLOCK_LOCAL=UNKNOWN`，不得用泛化TIMESTAMP偷填现实时间。
- `SETTLED_BY_COMMIT_ID`引用章节/维护事务COMMIT_ID；总线记录是否可作为正史输入由对应事务日志状态决定，不另设第二提交开关。
- BUS记录是一次不可变路由记录，不设BUS_REVISION；若路由参数/目标需要正式修正，创建新`BUS_EVENT_ID`并用`SUPERSEDES_BUS_EVENT_ID`指向旧记录，旧记录保留。

## 路由示意
资源稀缺 → 90 → 88势力决策 → 89事件候选 → 91情报 → 92舆论（若传播）→ 94因果。
关系权限变化 → 39—46 → 六专项（若相关）→ 7K候选（若有关系窗口）。
世界事件 → 87时间 → 88/89/90/91/92/93/94 → 79—86评估。
偏航记录 → 仅当`FACT_TYPE=DEVIATION_RECORD`正式成立时，以该FACT作为SOURCE_ID路由；不自动广播“爱情含义”，也不创建独立DEV总线主键。

## 防级联失控
- 只有RELEVANT系统接收。
- MAX_CASCADE超过阈值触发84/86。
- 同一客观事实只保留一个FACT/EVENT源，其他系统引用。
- 不允许“发生一件事→所有15男主立刻知道/吃醋/出手”。
