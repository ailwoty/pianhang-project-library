# V12正文运行态｜伏笔生命周期与回收路径 V5

状态：ACTIVE
SCHEMA_VERSION：5
来源：V12 FINAL 7D.28（规则476—494）及与其共享生命周期的长程/轮回伏笔规则
性质：现有第28号伏笔自组织演化系统的运行账；**不是新增系统**。

## 1. 单一事实源原则
伏笔账只登记“未来可回收结构及其生命周期”，不复制客观事实本体。
- 已发生事实仍由`FACT_* / EVT_*`承载；
- 证据仍由`EVID_*`承载；
- 关系/资源/情报/舆论变化仍由各自运行账承载；
- `FSW_*`只引用这些节点并记录其未来回收结构、成熟条件与剩余问题。

## 2. FSW主记录
每一枚当前有效伏笔使用稳定`FSW_*`：

FSW_ID / FSW_REVISION / LIFECYCLE_STATE / ORIGIN_CHAPTER_UID / ORIGIN_WORLD_CLOCK / ORIGIN_FACT_IDS / ORIGIN_CLAIM_IDS / ORIGIN_EVENT_IDS / ORIGINAL_MEANING / CURRENT_MEANING / MINIMUM_EXISTENCE_EVIDENCE_IDS / ABSORBED_VARIABLE_REFS / EMOTION_SOURCE_REFS / COUPLING_LEVEL / MATURITY_CONDITIONS / PHASE_WINDOW / OVERDUE_PROTECTION / SETTLEMENT_STATUS / REMAINING_QUESTIONS / METAMORPHOSED_TO_FSW_IDS / LAST_CHANGED_BY_COMMIT_ID

### LIFECYCLE_STATE
只使用V12第28号系统的四态：
- `DORMANT`：休眠；保留最小存在证据，不要求频繁提醒；
- `GROWING`：发育；允许吸收新变量，但不得篡改原已锁事实；
- `MATURE`：成熟；至少一条回收路径具备因果、人物与时序条件，但不等于必须立刻触发；
- `METAMORPHOSED`：蜕变；第一次产生效果后，把未耗尽因果/后果/误读/声誉/秘密残留/关系变化转化为下一枚伏笔。

`FSW_REVISION`是单个FSW内部局部正整数版本；首次正式建立=1，生命周期/意义/成熟条件/路径/结算等持久变化时递增。
`LIFECYCLE_STATE`不承担“是否正史”功能；记录是否有效仍由`LAST_CHANGED_BY_COMMIT_ID`所指事务是否COMMITTED决定。

### SETTLEMENT_STATUS
`NONE / PARTIAL / FULL`
- `PARTIAL`必须填写`REMAINING_QUESTIONS`；
- 部分回收后可继续`MATURE`或进入`METAMORPHOSED`，不允许把剩余问题假装已结清；
- `FULL`只表示当前伏笔主体完成信息/情绪/世界后果三项结算，不删除历史记录。

## 3. 候选回收路径
同一FSW可维护多条局部候选路径；路径ID只在该FSW内部使用，不创建新的全局命名空间。

每条路径：
LOCAL_PATH_ID / CHARACTER_CONSISTENCY / EMOTIONAL_GAIN / PHASE_FIT / MAINLINE_SAFETY / DERIVATIVE_POWER / ORIGINALITY / WORLD_FEEDBACK / PATH_STATUS / REQUIRED_FACT_OR_EVENT_REFS / REQUIRED_RELATION_OR_RESOURCE_REFS

`PATH_STATUS`：
- `ACTIVE`
- `SEALED`：未选中但保留；
- `INVALIDATED`：与已发生事实冲突、被主线淘汰或价值严重衰减；
- `SELECTED`

候选评分服务择优，不得为了“回收伏笔”强迫人物做不自然选择。

## 4. 耦合与级联
`COUPLING_LEVEL=WEAK / MEDIUM / STRONG`
- WEAK：只共享主题/情绪；
- MEDIUM：共享人物、信息或利益；
- STRONG：共享关键因果节点。

强耦合同时触发必须进入级联审查。
一个伏笔触发时只唤醒必要关联项；禁止把独立事件硬串成单一幕后源头。

## 5. 发育吸收与情绪来源
`ABSORBED_VARIABLE_REFS`只引用已登记节点，如`FACT/EVT/REL/RES/INFO/NAR/CAUS/PROC`。
允许吸收人物新立场、圈层反馈、资源变化、认知偏误、隐变量、关系权限、时序相位，但只改变**回收路径**，不得改写原锁定事实。

`EMOTION_SOURCE_REFS`必须说明情绪重量来自哪些已发生关系/选择/事实；禁止后期只剩信息答案而没有情绪支付。

## 6. 成熟、过期保护与结算
- `MATURE`不是自动触发；仍服从相位、人物自然行动和重大节点Gate。
- 超长周期可启用`OVERDUE_PROTECTION`，寻找自然锚点维持可回收性；禁止反复生硬提醒。
- 回收强度匹配铺垫长度与价值。
- 正式结算至少检查：信息结算 / 情绪结算 / 世界后果结算。
- 长程/轮回伏笔共享本生命周期；不能临近回收才补写“其实一直如此”的伪伏笔。

## 7. T0与历史资产
当前正式第一章尚未提交，CURRENT运行账：
`FSW_RECORDS = NONE_COMMITTED`

这不表示项目“没有伏笔”。历史`V5_16_伏笔台账_60条.md`等只按资产路由的`FORESHADOW_ALLOWED`提供候选结构：
1. 首次真正使用前读取并与V12/V10/current facts核验；
2. 剥离旧章号、旧身份、旧揭露时间与冲突事实；
3. 只有通过兼容编译且进入当前章节/维护事务时，才分配新的`FSW_*`；
4. 未编译历史伏笔不得直接进入成熟队列、时间债或正文正史。

## 8. 与成熟队列/时间债
- `Q_*`可通过`VARIABLE_REF_TYPE=FSW`、`VARIABLE_REF_ID=FSW_*`追踪伏笔成熟；
- READY只表示可评估，不等于伏笔已回收；
- 伏笔只有在其底层FACT/EVT已经客观发生但尚未展示时，才可能进一步产生`TD_*`；S3/S6伏笔计划不能借时间债偷渡成既成事实。

## 9. 提交
任何新建/变更FSW记录：
- 必须在章节或`CM_MAINT_*`事务中声明；
- `LAST_CHANGED_BY_COMMIT_ID`绑定该事务；
- 事务日志未COMMITTED前仅是候选写入；
- 旧FSW ID不复用，蜕变用`METAMORPHOSED_TO_FSW_IDS`建立链。

REVISION_NOTE：2026-10-05 P333，FSW增加`FSW_REVISION`；同一伏笔的发育/成熟/结算/蜕变演化用revision追踪，不用新ID覆盖旧状态。
