## INFO节点字段
INFO_ID / ORIGIN_FACT_IDS / ORIGIN_CLAIM_IDS / INFO_REVISION / ORIGIN_CONTEXT / SOURCE_CHAIN_REFS / SOURCE_CHAIN_NOTE / CREATED_AT / UPDATED_AT / HOLDER_IDS / CONFIDENCE / PERMISSION / PROPAGATION_SCOPE / LATENCY / DISTORTION / INDEPENDENT_VERIFICATION / SENSITIVITY / COMMIT_ID

规则：
- `ORIGIN_FACT_IDS`只引用具体`FACT_######_v#`，`ORIGIN_CLAIM_IDS`只引用`CLAIM_*`；两者可一方为空，但不能用未定义FACT_BASE隐形主键。
- `HOLDER_IDS`只引用实体注册表中的人物/组织等真实持有人；“公众/某圈层”若未建实体，不得为填字段临时造ID，可通过`PROPAGATION_SCOPE`表达范围。
- `SOURCE_CHAIN_REFS`引用`INFO/CLAIM/EVID/KNOW/FACT/EVT`等稳定节点；`SOURCE_CHAIN_NOTE/ORIGIN_CONTEXT`只作解释，不承担事实外键。
- `CREATED_AT/UPDATED_AT`固定使用`WORLD_CLOCK_TOKEN`或UNKNOWN，表示INFO在故事世界中的形成/更新顺序；不得写Library修改时间、宿主机时间或COMMIT终结时间。精确故事本地钟点如确有来源，另用对应`*_WALL_CLOCK_LOCAL`可选字段；否则UNKNOWN。 事务物理终结时间只由事务日志`COMMIT_FINALIZED_AT`承担。
- `INFO_REVISION`只是INFO节点内部修订号，不自成ID；持久变化仍绑定`COMMIT_ID`。

## 传播边
INFO_EDGE_ID / INFO_EDGE_REVISION / FROM_HOLDER_ID / TO_HOLDER_ID / SPEED / TRUST / PERMISSION / DISTORTION_RISK / CONDITION / LAST_CHANGED_BY_COMMIT_ID

`INFO_EDGE_ID`格式：`IEDGE_######`；只表示情报传播图中的一条边。`INFO_EDGE_REVISION`是该边内部局部正整数版本，建立=1，速度/信任/权限/条件等持久变化时递增。`FROM_HOLDER_ID/TO_HOLDER_ID`引用已登记人物/组织等实体；`LAST_CHANGED_BY_COMMIT_ID`记录当前revision由哪次事务写入。不得使用关系账的`REL_*`，也不得继续写无类型的通用`EDGE_ID`。
