## 二、按状态工作的十步流水线

1. **确认对象级别**：`SEGMENT_QA / CHAPTER_QA / ARC_QA / VOLUME_QA / POST_COMMIT_AUDIT`，绝不把R003已COMMITTED当候选。
2. **合法启动写作**：满足V12前置生产闸；小说正文按约500字生成/修订，单片段八轮内检，交付用户确认，未经确认不得继续下一单元。QA审核不会创建`LOCAL_TEMP_SCOPE`或章节UID。
3. **片段冻结与基础硬检**：用户确认的片段先记录时间/指纹/批准范围。Q01/Q02/Q09/Q18/Q21/Q22为基本检查域，其余按段落触发；根级任何禁词/句长冲突必须人工回查。
4. **全章冻结**：所有片段确认后合章，冻结整章BODY hash、章节合同与V12源向量，不得拿旧报告审核新稿。核验世界时钟、章节合同、事实/信息/关系变化拟议值。
5. **QA-1硬核**：按Q01—Q22逐行做PASS/FAIL/NEEDS_SOURCE/NOT_RELEVANT，不得笼统写“已检查”；INFO权限、人物自利、现实机构、秘密与因果源必须有文字/运行来源。
6. **QA-2文学盲审**：五角色隔离记录至少一次；依据八维100分锚点审人物差异、故事有效变化、读者钩子、环境动作、现实回声；单纯字数、模型自评、工具总计数不是文学评分证据。
7. **工单与决定**：每条缺陷引用实际正文<=30字和CURRENT来源，P0/P1阻断，P2原则REVISE且只有明示批准豁免才可继续；缺关键来源HOLD而非PASS。
8. **受限返修与回归**：仅在用户许可的约500字段内修订；每段重做八轮内检、再次确认并冻结。任何BODY字节更改旧QA凭证先标STALE；人物/INFO/结构变化要求全章复核，普通局部至少复核相邻段及Q21。
9. **业务QA放行证据**：报告完整、源/规则/批准记录可验证、P0=P1=0、P2全处理、评分符合门槛之后可作业务质量裁决；**目前无真实CH2的QA_RELEASE_TOKEN**。QA16输出`SHADOW_MATCH_ONLY`只算辅助。
10. **独立V12正式提交与只读回归**：QA不会生成PREPARED记录。持合法生产授权者重做READ_GUARD、fresh PREWRITE/PREFLIGHT并遵守既有V12事务路径；提交后若需复审，进入`POST_COMMIT_AUDIT`，修改须走合法章节修订事务。

## 四、分支停止条件

```text
IF SOURCE_MISSING OR TXN_LEASE_NONTERMINAL: HOLD / REVIEW_ONLY
ELSE IF SEGMENT_NOT_USER_APPROVED: HOLD_NO_APPROVAL
ELSE IF BODY_OR_SOURCE_HASH_CHANGED: QA_STALE -> RETEST
ELSE IF P0_OPEN > 0 OR P1_OPEN > 0: REJECT
ELSE IF P2_OPEN AND NO_EXPLICIT_WAIVER: REVISE
ELSE IF AUTHENTIC_APPROVAL_MISSING OR REQUIRED_SOURCE_UNKNOWN: HOLD
ELSE IF QA_REPORT_COMPLETE AND CHAPTER_SCORE >= 85: BUSINESS_QA_PASS_ELIGIBLE
ELSE: REVISE / HOLD

BUSINESS_QA_PASS_ELIGIBLE != V12_COMMITTED
QA16_SHADOW_MATCH_ONLY != TRUSTED_RELEASE
POST_COMMIT_FINDING != AUTOMATIC_RETCON
```

对非整章仅局部QA，分数`NOT_APPLICABLE`；不得为凑85分给约500字片段虚构整章评分。任何仅由同一模型分角色进行的五视角审核需记录`SAME_MODEL_PROCEDURAL_SEPARATION`，不冒称五名独立人类。
