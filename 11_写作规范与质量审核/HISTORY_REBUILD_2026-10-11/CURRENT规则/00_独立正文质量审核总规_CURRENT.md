# 《偏航》独立正文质量审核总规｜CURRENT

## 全文生成与修改常驻闸｜PROSE_SOURCE_GUARD_V1｜2026-10-10

本节根据用户“第一章的问题在后续所有生成和修改中不要再出现”的明确要求增补；作用于所有卷、章、片段、续写、重写、润色、删减与扩写。修复的是来源实读及成稿兑现链，不增加故事事实，不替代V12事务。此前只针对第一章的来源核查在这里扩展为通用规则。

### 一、每次都执行的链路

1. **确定基准**：区分FIRST_DRAFT、WORKING_REVISION、CHAPTER_REVISION；记录用户最新候选/正式BODY与版本、此次范围、上下文。不得误用第一章首次创建的NONE前置。
2. **目录差分与逐项筛查**：读取当前母版目录、后置覆盖段和本任务涉及的最新项目目录。当前目录基线为94个编号子系统、112个非编号控制/专项条目，共206个三级条目；112包含7A/B/J/K的49条和7C—I的63条。条目不等于206个独立模型。每项标记必需、条件未触发或不适用，并写明原因；六大专项触发时召回7C—I对应历代增量，不以最后一代代替前代。禁止遗漏条目，也禁止全开机制挤占正文。
3. **实读与权威裁决**：必需模块和关联来源读取有效原段及最新修订，记录stable ID、版本、具体段落、摘录与使用状态。目录清点、文件名、摘要、旧聊天和关联箭头都不等于已读。冲突、缺源、旧人物名/旧核心人数、旧720章坐标必须先裁决；当前440章规划、当前人物档、曜京CURRENT按相应权威规则使用。历史资料只作追溯，隔离文件不默认调用，交接稿回到原始来源。
4. **编译为场景**：把来源落实为人物当下目标、情绪原因、主动选择、阻力、生活体验、动作后果和下一期待。每项适用来源必须有“来源摘录→输入设定→模块→场景作用→正文原句”；约束型来源可记录范围、检查方法与未越界证据，不强求正文重复资料术语。仅填来源列表一律不通过。
5. **成稿核验**：冻结文本后完成下列十四项检查。每项只能记录有正文证据、确有理由不适用、受控后续兑现或未实现；“准备写”“读过了”“出现关键词”不能算效果兑现。未实现项先返修，不以禁词、字数或总分抵销。
6. **改后复核**：正文有变化则旧审核失效。局部修改至少重查改动、相邻段及受影响来源；事实、时间、视角、动机、关系、秘密、伏笔或章节结构变化时扩至全章，必要时检查前章尾与后章计划。保留修改前已成立的环境、阶层体验、魅力、幽默、心理、伏笔与兑现，不因压字数静默删除。
7. **交付与正式提交分开**：证据工具输出EVIDENCE_CHECK_PASS_EDITORIAL_REVIEW_REQUIRED只表示可继续文学审核；同模型编辑判断标记AI_EDITORIAL，不冒充真人试读。正式正文仍需有效PREWRITE及原事务；本次维护使旧PREWRITE不可复用，不产生新故事提交。

## 1. 审核目标与客观约束

质量审核不负责“把每个句子变得更华丽”，而是判断：读者是否看得懂正在发生什么、人物为何这么做、这一章到底改变了什么、读者为何愿意进入下一章、代价是否在世界中留下痕迹。

同一章必须同时经得住五个视角：

1. **正史审计员**：事实、时间、地理、职业/法律权限、REL/INFO/FACT/PROC一致；不靠想象修补未知项。
2. **人物敌对审稿人**：找出任何人物变成剧情工具、临时降智、违背底层欲望或失去真实自利的地方。
3. **读者体验审稿人**：阅读时能否建立期待、获得兑现、承受变化、持续追读；强情绪不等于情绪有效。
4. **语言审稿人**：逐句检查根级禁令与真实声音，指出AI腔、同质化、无效描写和可预判的模板。
5. **社会后果审稿人**：高位人物行动对普通员工、患者、司机、媒体、投资者、公共服务和机构秩序的可见回声是否按场景需要出现；不能强制每章群像化。

五个视角可以由不同审稿会话或具有显式角色隔离的多轮审核完成。若同一模型执行，也必须先冻结作者稿并输出具体证据，不能以“我已自查通过”替代独立审核。

## 2. 审核对象与冻结规则

- `SEGMENT_QA`：单个约500字已确认片段，做局部规则、前后衔接、信息边界和即时情绪检查。不允许未经授权修改前后已经确认内容。
- `CHAPTER_QA`：整章候选，新增章节有效变化、场景结构、节奏、情绪峰值、承诺兑现、首尾钩子以及段间拼接检查。
- `ARC_QA`：连续3—10章或一个关键事件段，新增重复情绪、无成长的失败、时间债、权力后果和多男主人物差异审查。
- `VOLUME_QA`：每卷复核人物弧线、旧情信息释放、胜负机制、长期承诺与回收。
- `POST_COMMIT_AUDIT`：对已经COMMITTED章节只读检查；产生发现和合法修订申请，不自行修改BODY、DELTA或运行态。

审核对象必须固定 `CHAPTER_UID`、稿件来源路径、候选版本/指纹、审核范围、核验时间、上游依赖版本。修订之后源稿指纹变化时，本轮QA不得继续标记为有效PASS，至少重审改动区及相邻上下文；改动影响核心人物、事实、信息或结构时重做全章QA。

## 3. 四阶段审核流水线

### QA-0｜入口与权限

先执行项目根级前置指令。若涉及V12生产，先按正文唯一入口要求校验事务READ_GUARD与PREWRITE有效性。审核可以在生产闸未通过时提出离线结构问题，但必须标记 `REVIEW_ONLY / NOT_SUBMISSION_ELIGIBLE`，不得假装正文具备正式开写/提交条件。

读取与本章有关的最新有效人物主档、章节合同、世界/组织/协议边界、上一章COMMITTED正文与DELTA以及INFO/REL/FACT/PROC相关状态；只为有证据的字段下结论。不可得资料标记 `UNKNOWN_SOURCE / VERIFY_BLOCKED`。

### QA-1｜硬门槛审查

按《缺陷分类判定与否决矩阵》逐项检查用户明确的语言禁令、职业能力和正史、信息来源、因果、人物动机与提交边界。任何阻断项存在时记录证据并裁定 `REJECT`，无需先计算综合分。

### QA-2｜文学效果盲审

不看作者的意图解释，只看成稿证据。按人物、关系、事件、情绪、场景、对白、社会回声、叙述节奏、钩子与语言差异评分。必须给出正文位置和读者实际会经历的认知/情绪效果；“很燃”“很虐”“很高级”不构成评价证据。

### QA-3｜交叉核对与返修

对每个缺陷建立工单，分配严重度、确定影响域、给出**最小必要改动建议**和回归验证方式。修改权属于受授权写作者；审稿者不能私自生成“修好了”的正式正文。返修后的版本重新走相关QA，保留失败轮次与差异证据。

## 4. 独立审核与八轮内检的边界

根级八轮内检先执行，独立QA不能减少八轮，也不把八轮报告复制过来冒充质量报告。

独立QA需要主动寻找**违背作者原始目标但被作者自身合理化的缺陷**：例如男主看似深情实则没有自我代价，女主看似聪明但只靠全知旁白取胜，修罗场看似刺激却所有人突然不懂保密，读者以为出现大反转但下一章的FACT/INFO/REL完全没变。

若作者与审核员意见冲突，以可引用的本章文本、对应CURRENT来源和可解释的读者效果为证；主观审美分歧可记录 `EDITORIAL_DISAGREEMENT`，但事实性P0/P1不能以平均分抵消。

## 5. 严重度、裁决及最小放行要求

| 等级 | 定义 | 处理 |
|---|---|---|
| P0 致命 | 违背明确硬规则或已COMMITTED正史、越过V12事务、关键未知变既知、核心人物设定或时间因果完全断裂 | 立即REJECT，需修订与全项复核 |
| P1 阻断 | 主线/关系/动机存在不可自洽断点；以全员降智实现修罗场；公开秘密无可靠路径；重大无后果行为 | REJECT，必须修订；若证据缺口导致无法判断则HOLD |
| P2 重大 | 相似情绪和对白大面积重复、人物优势没有真实成本、场景冲突缺乏有效变化、重要配角只有工具性、钩子失效 | 原则REVISE；明确例外须留理由且不得与P1混淆 |
| P3 一般 | 局部AI腔、环境空转、描写堆叠、衔接不顺、轻微冗余 | 记录返修，允许在无上级缺陷时合并处理 |
| P4 建议 | 合法可选的美学强化建议、表达口味分歧 | 不构成阻断 |

`PASS`必须同时满足：P0=0、P1=0、无缺证而强判PASS、源稿指纹有效、所有硬禁令通过、评分门槛通过、审核报告完整、已确认片段未被私改。P2若仍存在，默认不能PASS；只有有明确作者批准、影响隔离和理由的独立豁免记录时可记 `PASS_WITH_WAIVER`，仍不可掩盖P0/P1。 `HOLD` 表示证据或权限不足；绝不是默认PASS。

## 6. 分值是诊断，不是交易

用八维100分观察写作表现：人物可信与分化20、信息差/认知有效性15、因果与成本15、情绪与节奏15、对白辨识12、场景/社会回声8、语言自然度10、章节有效变化5。每维0—满分，附证据；建议综合分≥85方可作为高质量候选，75—84标记定向返修，低于75重构。任何P0/P1及来源不明的关键判断优先于分数。

禁止为了刷总分重复加煽情段落，或通过某一维高分补偿硬逻辑破产。

## 7. 版本、工单和证据规则

每个发现至少记录：`DEFECT_ID`、对象范围、行号/段号/原句短引、对应规则ID、严重度、损害机制、上游证据、修复约束、责任方、复核结果、状态（OPEN/FIXED/WAIVED/BLOCKED）。

不得凭阅读印象制造不存在的原句，不得把用户未确认的设定当正史，不得在审核报告中编造读者投票/平台数据/转化率。

只允许对**候选**提出改动建议；已提交正文必须创建 `POST_COMMIT_FINDING`、确定是否RETCON/CHAPTER_REVISION，并走正式变更链；审稿报告绝不直接修改正式正文索引/世界时钟/DELTA。

## 8. 提交接口与索引联动

最低过程：`八轮内检 → 500字段落用户确认 → 片段QA → 合章QA → 可选跨章QA → QA放行凭证 → V12正式事务（按既有规则） → POST_COMMIT只读回归`。

QA凭证字段：`QA_REPORT_ID / SUBJECT_FINGERPRINT / CHAPTER_UID / QA_SCOPE / QA_RULE_VERSION / QA_VERDICT / BLOCKERS / SCORE / SOURCE_VECTOR / APPROVED_BY / REVIEWED_AT`。

正式生产是否已经纳入强制QA字段，需由V12运行控制层依法维护与接线；本规范自身不擅自扩充V12 Manifest、事务日志或PREWRITE硬闸。在接线完成前，可将QA放行作为业务上的独立提交前检查，不能声称运行时机器校验已生效。

## 9. 防刷分与反规避

- 重复缺陷不因同类出现多次被合并成“一个小问题”：记录不同位置与累计范围。
- 审稿必须包含反例检验：若把这名男主换成另一名、把秘密去掉、把环境删掉，场景是否仍原封不动？若是，高概率存在同质化/空转问题。
- 对关键反转做“取证链审查”：信息从哪里来，谁何时拿到，为什么相信，在什么代价下行动。
- 对重大“霸总式解决”做“机构摩擦审查”：员工、流程、财务、法律、监管、媒体和公众视角至少有可解释的响应机制，不要求每次都把这些写成篇幅。
- 审核员必须明确区分“读者尚不知道”与“作者尚未规定”；后者不得被审稿人脑补为答案。
